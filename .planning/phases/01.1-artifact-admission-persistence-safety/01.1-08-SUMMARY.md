# Phase 01.1 Plan 08: Runtime Artifact Admission and Safe Persistence Summary

**Runtime execution now starts from admitted safe artifacts plus explicitly transient material, while state, index, environment, message, output, and replay evidence remain exact, value-blind, and fail-closed.**

## Performance

- **Duration:** 39 min
- **Started:** 2026-07-12T09:27:45Z
- **Completed:** 2026-07-12T10:06:51Z
- **Tasks:** 2/2
- **Execution mode:** generic-agent GSD executor workaround
- **Commits:** none (not authorized)

## Accomplishments

- Added strict runtime-plan/run-state/run-index descriptors and exact command subjects. `run-plan` admits blueprint bytes, `run` admits runtime-plan bytes, report/replay/eval admit run-state bytes, and status exact-loads state or index+state.
- Removed the blueprint-to-run compatibility route and every durable inline/file message carrier. Runtime plans contain a `<transient-message>` template plus digest/length/summary; runner-only materialization receives the actual message and host paths.
- Replaced environment metadata with exact `SecretPresence` and all message/stdout/stderr persistence with exact `RedactedSummary` carriers. Policy prose and unsupported surfaces are digest-only runtime descriptors.
- Rebuilt state/index persistence around complete preflight. Invalid nested env/output/fallback/selector candidates cause no directory, state, index, temp, or message artifact; valid index entries bind the exact serialized state digest.
- Made replay truth explicit: newly supplied matching bytes are `exact`, mismatches are `reconstructed`, absence is `unavailable`, and exact-required rejects before spawn or write.
- Preserved composed birth/delivery semantics by comparing run-state blueprint lineage with build-state exact blueprint provenance, without restoring a weak runtime JSON hash.
- Reduced transitional blueprint consumers from five to three; Plan 10 owns the remaining birth/domain/delivery consumers.
- Closed a newly exposed nested-provenance last-wins gap by recursively detecting duplicate `identity/subject/digest` members while preserving existing top-level identity rules.

## Decisions Made

- Made `buildRuntimePlan` async so it can authenticate blueprint admission through a dynamic import without creating a registry/admission initialization cycle.
- Kept runtime-plan authoritative for provider/model/selector/timeout choices. `run` may re-supply only execution material such as message, workspace, source/state paths, and environment values.
- Used digest-only target/profile policy descriptors instead of weakening persistability for runtime artifact prose.
- Stored run-state lineage as `{input, blueprint, runtimePlan}` exact provenance. Replay changes `input` to the admitted parent state while preserving blueprint/runtime-plan ancestry.
- Used a sorted run-index entry array so an arbitrary valid run id never becomes a secret-like object key; duplicate ids and unsorted entries fail validation.
- Kept CLI stdout/stderr explicitly pending Plan 11 even though runtime JSON candidates are safe.
