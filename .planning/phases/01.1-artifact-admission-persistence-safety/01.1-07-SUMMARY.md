# Phase 01.1 Plan 07: Scaffold/Build-State All-Set Persistence Summary

**Scaffold and status now enter through exact blueprint/build-state contracts, and an unsafe file anywhere in the planned package cannot create even the scaffold root.**

## Performance

- **Duration:** 32 min
- **Started:** 2026-07-12T07:58:30Z
- **Completed:** 2026-07-12T08:30:16Z
- **Tasks:** 2/2
- **Execution mode:** generic-agent GSD executor workaround
- **Commits:** none (not authorized)

## Accomplishments

- Added the `agentmo.build-state.v1` durable descriptor and strict validator. New state is exact, persistable JSON with admitted blueprint provenance, a managed `.` output-root reference, deterministic resolution data, and SHA-256 content digests for every domain operation.
- Removed all durable `blueprintPath`, `outputDir`, and `destinationPath` fields. Target verification instructions are represented by digests rather than path-bearing command text.
- Migrated `scaffold` and `status` from `loadBlueprint` to `loadAdmittedBlueprint`, reducing the frozen transitional map from seven consumers to five. No Plan 08 or Plan 10 command was migrated early.
- Defined `status` as required `blueprint` plus path-conditioned optional `build-state`. Missing, duplicate, extra, mutated, wrong-family, unknown, legacy, and mismatched-source bindings fail before snapshot logic.
- Required authentic blueprint admission in `scaffoldAgent` and `createBuildState`. A forged admission cannot produce a root or build-state.
- Rebuilt scaffold application around all-set preflight: exact operation object descriptors, known `write-file` kind, managed ownership, sorted relative paths, no traversal/absolute/backslash/NUL, no state-sidecar collision, no exact/casefold/prefix collision, every copied content byte candidate, and final build-state serialization are validated before any writer.
- Added pre-write symlink component rejection for existing `--force` targets and wrote only the already-validated copied bytes through managed atomic writers.
- Made OpenClaw durable workspace references portable (`openclaw/workspace`) and converted known runtime-profile host locations into non-authoritative portable references. Two scaffold roots now produce byte-identical domain files and build-state.
- Added a private capability brand for schema-owned product text so prompt/skill policy language remains ordinary package data. The helper still rejects credential-like values and concrete host paths and cannot be forged into the writer.
- Updated only bounded compatibility paths: direct scaffold tests now provide authentic admission, CLI journeys provide required digest bindings, and birth/delivery understand the new non-certifying source provenance shape.
- Reclassified every Plan 07 scaffold/build managed operation and physical writer as `gated`; all CLI output rows remain `pending:01.1-11`.

## Decisions Made

- Introduced a new build-state identity instead of silently tightening `agentmo.build.v1`. The old format cannot prove the exact blueprint bytes and therefore must not be transformed into false admitted provenance.
- Kept old build-state migration normalization separate through the legacy canonical validator. It preserves legacy evidence without making it admissible as `agentmo.build-state.v1`.
- Made `createBuildState` asynchronous so it can authenticate the admission result without creating a registry/admission ESM initialization cycle.
- Treated `generatedAt: null` as the deterministic default. A caller may supply a real timestamp explicitly, but default build bytes do not claim one.
- Required status to cross-check build-state provenance against the exact blueprint admission. Separately valid files are insufficient if they describe different agents or blueprint bytes.
- Used a branded product-text lane rather than weakening the general persistability kernel. Raw runtime/evidence fields remain rejected by admission; schema-owned policy prose does not become runtime evidence merely because it mentions a prohibited data class.
- Kept path resolution transient: operation destinations are computed only at the physical write boundary from an already validated relative path and output root.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Identity integrity] Split new exact build-state identity from the legacy build format**

- **Found during:** build-state descriptor design and legacy migration audit.
- **Issue:** Reusing `agentmo.build.v1` would either accept host-path legacy state under a tightened descriptor or require relabeling a stable-object hash as an exact byte digest.
- **Fix:** Added `agentmo.build-state.v1`; kept `agentmo.build.v1` only in legacy validation/migration semantics.
- **Verification:** exact loader cross-product, legacy migration suite, and full repository gate.
- **Commit:** none.

**2. [Rule 1 - Product data compatibility] Added a capability-branded schema-owned product-text helper**

- **Found during:** first all-operation preflight GREEN attempt.
- **Issue:** The general evidence writer intentionally rejects runtime-material phrases and its conservative host-path detector also flags valid package references such as `./bin`, `../pi`, and `<workspace>/skills`.
- **Fix:** Added a private branded lane that permits policy language/portable references only after original text passes secret and concrete-host checks; forged wrappers are rejected.
- **Verification:** product-text unit test, hostile scaffold zero-root matrix, I/O inventory, and full suite.
- **Commit:** none.

**3. [Rule 1 - Bounded compatibility] Updated existing scaffold/composed consumers for authentic admission and new provenance**

- **Found during:** first full-suite pass.

- **Fix:** Added only the required admission/digest bindings and non-certifying provenance compatibility. Runtime/run-state subjects remain untouched for Plan 08; report family closure remains Plan 10.
- **Verification:** protection 120/120, compatibility 85/85, repository 356/356.
- **Commit:** none.

- **Verification:** scaffold focused tests and repository gate; the remaining race window is disclosed below.
- **Commit:** none.

## Issues Encountered

- OpenClaw config and runbook originally embedded the absolute scaffold root, while the Win9 runtime profile also contained absolute source/owned-surface references. Persisted workspace authority is now relative, and known provenance surfaces are rendered as portable references.
- The I/O scanner deliberately flags all `kind: write-file` checks, including validator checks. The new build-state validator operation row is therefore recorded as a Plan 07 gated operation surface rather than hidden as a false negative.
- `status` initially admitted blueprint and build-state independently. A second audit identified the confused-deputy case where two exact but unrelated artifacts could be combined; source provenance and agent id are now cross-checked.
- Duplicate identity scanning previously covered only legacy build-state source keys. It now also rejects duplicate `source.identity`, `source.subject`, and `source.digest` before JSON last-wins parsing.
- The single required live `rg` call was used once for Plan 07 loader/builder/CLI/test inventory. All later call-site checks used direct reads or `grep`.
- The pre-existing dirty worktree was preserved. No `.env` content was read, printed, summarized, copied, or exposed.
