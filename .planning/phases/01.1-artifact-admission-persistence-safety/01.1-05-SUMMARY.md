- Added frozen `migration-input-0..N-1` subject derivation and wired `migrate` through the existing exact binding parser, so every path has one externally supplied digest and no binding is ignored.

## Decisions Made

- Kept CLI binding ordinals zero-based because they address input array positions directly; kept existing plan item ordinals one-based because they are human-facing receipt/report identifiers.
- Used the existing `parseDigestBindings`, `digestRawBytes`, and `assertPersistable` APIs without modifying the shared admission or persistability kernels.
- Counted one read as one complete retained-handle capture, not one kernel read syscall: large inputs may require multiple bounded chunk reads, but each preview/apply pass opens each source file once and never reopens it for digest or parsing.
- Retained both the initial source/output-parent separation check and a second identity comparison inside the retained source capture. The latter binds the exclusion to the directory actually supplying the bytes.
- Kept marker directory identity because the committed verifier relies on it. A safe template is gated before `mkdir`, then the actual identity-specific bytes are gated before any marker/payload/receipt handle opens.
