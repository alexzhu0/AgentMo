<domain>
## Phase Boundary

本 phase 交付 exact-raw-bytes digest admission、closed durable-artifact loader registry、fresh-process handoff，以及覆盖所有当前持久化 writer 的统一 SecretRef/value-blind policy。

本 phase 不处理 OpenClaw Node runtime 门槛、真实 Node 20 lane 或 release matrix；这些能力属于 Phase 1.2。它也不实现后续的 Package compiler、安装生命周期或领域质量认证。

</domain>

<decisions>
## Implementation Decisions

### 跨阶段工件权威
- **D-13:** 下游阶段只依赖有效 schema、独立可信的 exact-raw-bytes digest 和 admission，不依赖同一会话的命令 ancestry。loader 必须对同一份 raw bytes 先校验 digest，再解析、审计与 schema validate。

### 已批准拆分继承的验收约束
- durable-artifact identity 到 validator/legacy-inspector 的映射必须是 closed registry；未知 identity 失败关闭。
- 每个当前普通 loader 必须明确属于 canonical admission、legacy migration-required 或不适用三者之一，不得落入模糊 generic rejection。
- 当前 writer 在序列化、写文件或输出可持久证据之前执行共同 persistability gate；允许内容只有 `SecretRef`、存在性或脱敏摘要。
- hostile material 位于嵌套 value、object key、subject、pointer、raw prompt/transcript/tool body 或 stdout/stderr 时，必须 value-blind 失败并保持零写入。
- 所有当前生成、脚本化和维护文档中的 durable-input 命令都必须携带与每个 subject 一一对应的 digest binding。
- `declared-ready`、`live-success` 与领域 eval/production approval 继续保持非传递证据语义。

### the agent's Discretion
- admission/persistability 模块的内部 API、registry 表结构和测试 helper 组织。
- CLI digest flag 的精确语法，只要支持多个输入的一一绑定、拒绝缺失/重复/未知 subject，并且 human/JSON 行为可测试。
- writer integration 的计划拆分，只要 inventory 有 closed owner、同 wave 不修改同一文件，并且不存在未接线的当前 writer。

</decisions>
