## Phase Boundary

<decisions>
## Implementation Decisions

### Core 与 Target Runtime 分离
- **D-14:** AgentMo core 支持 Node.js `>=20`。所有 OpenClaw target mutation 必须读取真实 runtime evidence，并在任何写入、状态目录创建或子进程副作用前强制执行 `>=22.19.0 <23 || >=23.11.0`；生产调用者不能注入兼容版本绕过门槛。

### 已批准拆分继承的验收约束
- 真实 Node 20 lane 必须实际运行 core check 与关键 contract tests；`engines.node`、mocked `process.version` 或声明性矩阵不能替代执行证据。
- runtime assertion 位于最低、所有生产 mutation 必经的 spawn/mutation seam；上层 scaffold、run、replay 和 shell live-smoke 均不得形成旁路。
- 不兼容 target runtime 时必须证明无 OpenClaw state、目标文件和子进程副作用。
- CLI、生成 runbook、shell helper、维护文档与测试使用同一 runtime range 和失败语义。
- release record 只记录实际观察到的命令、状态、范围和 remaining risk；runtime smoke 不得升级为领域质量或生产认证。

### the agent's Discretion
- Node 20 lane 使用本地可用 runtime 还是 CI matrix，只要执行证据确定、无 secret 且未运行时明确标为 untested。
- target runtime probe 与 assertion 的模块边界，只要生产 seam 不暴露 version-provider bypass，测试替身保持私有。
- shell helper 是调用共同 gated seam 还是在每个直接 mutation 前执行同一不可绕过 assertion，只要负向测试证明零副作用。

</decisions>

<code_context>
## Existing Code Insights

- `src/runtime-execution.js` / `runRuntimeCommand` 是当前 child-process seam 的首要候选，但规划时必须证明所有生产 mutation 都经过它。
- `src/scaffold.js`、live run/replay 路径与 `scripts/openclaw-live-smoke.sh` 需要统一审计；shell 中直接调用 OpenClaw 的路径不能依赖上层偶然 preflight。
- `test/live-smoke-script.test.js` 与 runtime/scaffold tests 应覆盖不兼容版本下的零状态目录、零 spawn、零目标文件副作用。
- release matrix 必须分别表达 AgentMo core Node range 和 OpenClaw target Node range，并区分 declared、tested、untested。
