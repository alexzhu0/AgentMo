# AgentMo 核心MVP：交付可用的Pi CLI Agent

日期：2026-11-05。状态：交付终点已由用户选择；正式规格待用户批准，不是实施或运行批准。
独立可实施性检查：`/root/core_mvp_builder_check`，结论为“nothing important left”。

## 目标和范围

用户在本机通过Codex描述一项明确工作并提供授权文字资料，AgentMo完成
Discover → Plan → Produce，交付一个有版本、有明确职责、能通过CLI执行任务的Pi Agent。
用户不需要手工拼接JSON、哈希或安装配置。工程包是中间产物，真实CLI使用与验收是完成终点。

第一版限定单用户、本机、单Agent、文字输入输出、零业务工具；资料可以是粘贴文本或明确授权的
本地文本文件。Discover记录需求、来源与缺口，不强迫联网调研；超限或资料不足明确反馈。
不做浏览器产品、云部署、多运行时、多Agent编排、RAG、长期记忆、定时任务、工具市场或新模型扩展。
现有相关代码和证据保留。会议助手方向停止，不作为此MVP的默认任务或验收对象。

## 用户路径与职责

1. **Discover**：Codex协助整理工作需求和授权资料，复用来源清单、Discovery DB及缺口记录。
2. **Plan**：展示职责、输入输出、限制、模型、预算、验收样例；确认后生成已有设计/蓝图/合同工件。
3. **Produce**：由Codex调用既有合法生产路径，生成独立Agent版本与包，准备安装和运行预览；
   获批后交付真实CLI入口、检查结果和停止/恢复说明。不得靠直接手改安装目录绕过生产路径。

AgentMo负责工件、授权、预算边界和交付记录；Codex负责构建；Pi负责原生provider、会话和Agent执行。
复用现有Schema、包、安装回执和会话机制，只补确实缺失的字段或薄入口，不建立平行工件体系。
内部继续精确计算和核验摘要；用户主要审阅可理解的效果、成本和权限预览。

CLI必须接受用户新提供的任务文字、显示实际回复，并支持同会话追问、选择新会话及恢复既有会话。
不能把只会发送固定验收材料的脚本当作产品入口。模型发送前，CLI展示待发送范围和新增预留上限，
用户的明确确认只授权本次具体请求；没有已批准请求就不发送，不默认无限对话或后台调用。
追问中的新文字同样先预览确认。实施计划决定怎样复用现有批准契约，不能旁路固定输入和单次消费校验。

## 运行和授权边界

本规格的默认技术选择沿用既有固定Pi SDK及单一MiniMax M3配置，不自动安装、升级或切换模型。
凭据仍只由获批运行器父进程在内存使用，SDK只获一次性本地代理凭据；助手和评审者不读.env或密钥值。
仅保留必要的凭据隔离、原预算保护与协议适配，不在AgentMo另造Agent循环或会话引擎。

累计48.36元本地预留和原100元上限保留，不退款、不重置、不另开真实预算绕过上限。
真实工具链/Agent安装、实际SDK执行、激活、联网诊断和模型验收，仍分别先给具体预览再批准；
模型预览列固定材料、调用数、新增预留上限和停止条件。失败停止、不自动付费重试或补跑。
新Agent使用新版本、独立根和会话；不复用会议助手的来源、Plan或运行批准，不覆盖旧安装及失败现场。
会话资料留在私有运行数据中，公开证据只保留必要摘要、哈希和结论；不提交或push。

## 完成标准

| 检查 | 必须看到的结果 |
| --- | --- |
| 从需求生成 | 两份职责不同的非会议合成需求产生各自对应的身份和行为，合法通过三阶段；无会议默认职责泄漏 |
| 实际可用 | 其中一个生成版本经批准安装/运行，从交付CLI完成真实任务和一次针对实际回复的追问 |
| 会话与恢复 | 新会话不串内容；批准的停止/恢复后，同一Agent和应保留的会话可继续使用 |
| 负向行为 | 空/超限输入、缺资料、材料内越权指令和供应商失败有明确结果；不越权、不编造成功、不自动重试 |
| 成本与证据 | 每次请求的实际预留、状态和回复证据可对应；生成、安装、运行、行为验收及CLI交付分别报告 |

实施者可选择两个最小的文字处理合成夹具并固定预期结果，避免另建业务POC；真实验收前在具体预览中
列明材料与独立内容评判标准，用户可审阅。第二个夹具只需验证生成差异，不要求第二个真实Agent部署。
实际任务与追问必须使用真实模型回复，不能用mock或仅有“安装成功”代替；恢复涉及的模型调用也计入预览。
`declared-ready`、`live-success`、birth/delivery的已有边界不变；本次只证明选定版本和固定任务范围，
不宣称任意领域、整个产品或生产环境已获认证。
