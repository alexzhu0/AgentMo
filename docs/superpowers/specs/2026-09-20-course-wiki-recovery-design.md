# Course Wiki 恢复与 AgentMo 行为验收设计

日期：2026-09-20。状态：设计与实施计划均已获用户确认；实施中，未完成验收。
本文不是实现计划、阶段审批、安装授权或运行成功证据。不得自动提交或发布。

## 1. 目标与完成边界

用户选择 DOCX、Markdown、UTF-8 TXT 文档，在本机生成可浏览的中文 Wiki，
随后在 OpenClaw 的 course-wiki agent 中针对这些材料交流。必须能够处理问候、
追问、切换话题、材料不足及失败后的下一轮问题；答案引用可核验原文。

同时提升 AgentMo：把明确的产品行为要求连接到真正执行过的验收证据，复用已有
domain-eval / delivery-report，而不是把服务连通、引用合法或模拟测试通过当作交付。

保留三个独立状态：固定样本演示、可导入文档的可用 POC、AgentMo 正式全链路证据。
前者不能自动证明后者。正式 Discover / Plan / Produce 仍遵守原有独立审批。

范围保持单用户、单活动知识库、本地受监督运行。每批 1–10 个文件，每文件最多
2 MiB，提取正文合计最多 100,000 字符。不支持 DOC、PDF、PPT、OCR、音视频、
云同步、多用户或自动后台任务。Word 在本设计中明确指 DOCX。

## 2. 复用与职责

- OpenClaw 负责原生聊天入口、agent 身份和会话；不重写聊天 UI，不修改其分发代码。
- 现有本地资料页只负责文档选择、导入确认、Wiki 浏览、原文查看和状态显示。
- 复用 course-wiki-documents 的解析、大小限制、摘要和引用定位。
- 复用 OpenClaw memory-wiki 的 ingest / search / get / compile / lint 和隔离 vault。
- 现有适配层负责证据选择、回答协议、引用核验、费用与错误边界；模型不获通用工具权限。
- AgentMo 复用 requirement→eval 关联、domain-cases、domain-eval 和 delivery-report。
  新增的是可执行的行为验收及其证据生成，不新增第二套评测报告框架。

不采用仅补提示词的路线：无法补齐上传、证据和真实多轮验收。
不采用重写 OpenClaw / 新建向量数据库路线：目前没有证据证明需要这些替换。

## 3. 先定位消息问题，再调整行为

先以受控公开测试输入核对三处边界：原生入口收到的本轮输入、适配层收到的末轮
用户消息、发往模型的末轮用户消息。仅持久化测试 case ID、角色序列、长度、摘要、
相关标记是否存在及结果状态；不保存原始请求、回答、transcript 或凭据。

对比新会话和含一次失败的会话，分别验证问候、追问和切换话题。不清除旧会话来
掩盖问题。不得仅因看到 OpenClaw 的 orphan-repair 代码就声称它是本次根因。
如果证据显示输入在 OpenClaw 内丢失，先报告具体边界，不通过猜测性历史删除绕过。

保留会话历史用于指代消解，但本轮明确输入优先；历史中的未完成问题不自动变成
当前任务。不要用截取最后一行或匹配 OpenClaw 文本标记的脆弱方法提取实际问题。

## 4. 回答行为与引用边界

内部回答改为明确的三类，不把普通交流冒充缺证据：

| 类别 | 用途 | 引用约束 |
| --- | --- | --- |
| conversation | 问候、功能说明、必要的澄清 | 空引用；不承载教材事实性解答 |
| grounded | 材料内问题与有明确指代的追问 | 至少一条精确摘要/行号引用 |
| insufficient_evidence | 当前提供的证据不足 | 空引用；明确不足，不补写常识答案 |

模型只选引用位置；程序从已验证来源提取原文。不得模糊修复摘要、行号或伪造引用。
结构校验不能证明语义正确：conversation 绕过引用、答非所问、引用不支持结论等
由明确行为用例及独立审查检查，不宣称已获得任意输入的确定性语义防护。

输出错误应区分输入不合法、模型格式不合法、来源校验失败、上游不可用、预算不足。
模型输出错误不统一冒充 request schema 错误。不自动重试收费；旧失败保留可见，
用户的新问题仍可独立执行。错误码不得包含原始 provider 内容或密钥。

## 5. 文档导入、使用授权与版本

上传先在本地解析和预览，默认不传给模型。界面展示文件列表、来源摘要、正文规模、
所用服务及“将这些材料用于生成与问答”的明确确认动作。确认绑定精确材料集合；
替换或新增材料不能继承旧集合的授权。历史三个样本的 campaign 保持原义。

复用现有 stage 后切换的导入方式。新集合先完成解析、原生 ingest、来源映射核验、
Wiki 生成及 lint，成功后才成为活动集合；失败保留旧版本，不部分覆盖。
重复导入同一集合不增加重复来源或自动再次收费，显示已有结果；主动重新生成是
单独可见操作。活动请求持有固定集合版本，切换不得混用新旧引用。

导入后的 agent workspace 不再靠永久冻结来阻止更新；由应用在无活动请求的边界
生成并核验新工作区内容，再切换活动版本。更新只作用于 course-wiki 自有路径，
不得覆写用户其他 agent、默认模型或历史会话。切换失败时继续使用旧完整版本。

## 6. Wiki 与证据规模

Wiki 的中文主题由当前授权材料生成，不再强制恰好三份来源或三个主题。每个主题
保留精确引用，未覆盖的材料明确列出，不能用标题列表冒充语义 Wiki。

不能把最多 100,000 字的正文全部塞入每轮系统提示。工作区保留规则、来源目录和
简短 Wiki 导航；适配层复用原生 search/get 选取有界正文，保留中文问英文材料的
查询转换能力。预算核算覆盖转换、生成和问答的每次实际调用。

检索无结果不等于整库没有答案：回复必须区分“当前未检索到充分依据”和经完整
小语料核对后的不足。超过模型上下文预算时明确限制，不静默截断后宣称完整覆盖。
跨文档验收要求检索并引用相关文件；不能以单文档正确作为跨文档通过。

## 7. AgentMo 验收提升

为每项需求提供稳定 case ID、输入步骤、预期行为、硬失败条件和证据来源。
执行器使用实际 course-wiki 原生入口，机械检查覆盖传递、引用、预算、持久化；
独立审查按 rubric 检查切题性、依据支持和澄清质量。自报的模型评分不单独构成通过。
证据不足、未执行或评审未完成均不能生成通过结果。

用已有 domain-cases 字段承载经审查的结果和脱敏 evidenceRefs，再经现有 admission、
domain-eval 和 delivery-report 核验。把验收用例清单与 blueprint 的 required_case_classes
及需求关联绑定；不要修改通用合同加入英语教材专用语义。
仅有设计关联而没有真实执行证据时，交付状态必须仍显示缺口。

| 必验项 | 成功条件 |
| --- | --- |
| 问候与功能说明 | 正常交流，无旧题答案、伪造引用或虚构能力 |
| 材料内定义 | 中文解释切题，原文支持结论且位置精确 |
| 同会话追问 | 正确处理指代；歧义时澄清，不重复固定答案 |
| 切换话题 | 最新明确问题优先，不擅自续答旧任务 |
| 材料不足 | 有用且明确的不足说明，不是解析错误或常识补写 |
| 失败后恢复 | 一次受控失败后新问题可答，不自动重试旧收费请求 |
| 新文档导入 | DOCX/MD/TXT 各自通过本地选择、确认、Wiki 与原生 QA |
| 跨文档 | 结论引用相关多个来源，不能只提供单来源 |
| 更新与重复 | 相同集合不重复；替换不混引旧内容；失败保留旧集合 |
| 重启 | Wiki、来源和活动集合可恢复，原生聊天仍能查询 |
| 注入与费用 | 文档命令不执行；预算不重置、超额拒绝且无自动重试 |

所有必验项通过才可称“本范围 POC 可用”。领域用例通过仍不等于生产就绪。

## 8. 协作、验证与授权

统筹负责集成、消息路径定位和真实入口验收。实现可按文档/版本流与行为评测分工，
仅在文件职责清晰、接口已确认后并行；独立审查者不替实现者自行宣告产品可用。
每轮反馈附失败 case、当前证据和复测要求，不以不停创建 session 代替闭环。

实现采用 TDD 和最小改动。完成聚焦测试、npm run check、git diff --check；如修改
Stage 2 或兼容性机制，再执行仓库要求的额外 gate。真实测试单列，不被模拟测试替代。
维护当日 release 及恢复文档，记录精确版本、检查结果、预算摘要和剩余缺口。

人民币 100 元是累计费用上限，不是每次或每个新 workspace 的额度；启用新的数据
集合不重置旧支出。不得读取 .env、持久化凭据/原始对话、自动提交、push 或发布。
本设计审阅通过后才编写实施计划；计划审阅和执行方式确认后再进入实现。
