# 本机隔离 OpenClaw 原生文字助手

日期：2026-09-29。状态：用户已选择本机隔离入口，并明确回复“通过”批准本书面规格。
分类：架构变更——正式 Package 与运行绑定新增显式 native-chat 分支。
本轮仅设计，不代表 Produce、安装、激活、付费运行或提交授权。

## 目标与已选方案

承接 [概念设计](2026-09-28-agentmo-concept.md) 和已完成的
[定义/规划/scaffold 基础](../plans/2026-09-28-native-chat-foundation.md)：
用户用一句需求发起构建，必要确认后，在 OpenClaw 原生聊天页使用会议文字助手。
输入粘贴文字，输出摘要、决策、行动项和未决问题；缺失负责人或日期标记“未说明”。
不以生成 Markdown、模拟测试通过或手工预置成品代替真正交付。

方案取舍已完成：

- 采用本机独立 OpenClaw 状态、工作区和回环聊天入口；复用已安装运行时。
- 不改现有网关：避免影响用户当前 Agent、凭据、路由和会话。
- 不迁到 Linux：本演示不新增服务器或部署环境。
- 不移植整套 Linux 强隔离安装机制，也不降低它的既有保护。

## 现有事实与缺口

1. native-chat 已贯穿 need、Plan、Blueprint、离线 scaffold；无工具/子 Agent。
2. `build-contract.js` 仍拒绝 native-chat；正式投影要求插件 recipe 与四类 hook，
   部分内容固定为 support-triage，不能直接用于会议助手。
3. 已安装 OpenClaw 2026.9.4 使用 `agents.entries`；官方 `agents add` 支持
   非交互工作区注册。实际有效权限仍需运行验证，不能只凭字段存在推断。
4. 正式 probe/config-patch 路径依赖 Linux `/proc/self/fd`；macOS 不能冒充支持。
5. Course Wiki 已有封闭子进程环境、原生注册、回环代理和共享预算实现。
   `startCourseBudget` 是单次有期限请求，不是长驻聊天代理；其领域逻辑不能照搬。
6. 9 月 29 日完整五段检查已通过，见 [验证记录](../../../release/2026.09.29.md)。
   这是实现前基线，不是本设计的实现证据。

## 正式工件：增加窄分支，不建立平行构建流程

仍走 Discover → Plan → Produce。定义中的 `execution_profile: "native-chat"`
必须逐级绑定到 Build Contract、Package 和安装预览；未知值、跨级不一致拒绝。
缺省继续旧插件路线，旧批准不得被解释为新路线的授权。

- Build Contract 明确：OpenClaw 原生循环、单 Agent、业务工具为空、插件为空、
  不做 RAG/长期记忆/调度，无备用模型和自动付费重试。
- 保留资源账本的完整覆盖；不用的资源明确标记不启用，不生成占位工具、虚假
  数据库、embedding 配置或空插件来满足旧合同。
- carrier 增加严格的 `native-runtime` 变体，owner 为 OpenClaw；它不携带插件
  recipe、hook mappings 或可执行脚本。workspace 内容仍走现有声明式载体。
- 原生分支在合同、carrier、target admission、manifest、package projection
  校验中一致处理；不能只删除 Build Contract 的拒绝语句。
- 从已批准 Blueprint 渲染必要身份/行为文件，复用 scaffold 的实际渲染逻辑；
  任务名、目的、输出约束来自工件，不把会议文本模板写死为第二套 POC。
- Package 只含定义、工作区、配置意图及验收义务；不含生产路径、端口、密钥、
  原生会话或运行成功声明。新旧两条路线各自有正向与交叉拒绝测试。

## 本机绑定与生命周期

安装预览绑定同一 Package 摘要、已核验 OpenClaw 版本/执行文件身份、Agent ID、
新状态根、工作区、回环端口和预算引用。身份或摘要漂移后旧批准不可复用。
该绑定是 AgentMo 正式生命周期的显式分支，不是用户手改配置的操作说明。

2026-10-09 路径绑定补充（用户已批准）：持久工件仅保存 `stateRootDigest` 和
根内相对 workspace/agentDir，不保存本机绝对路径。运行入口单独接收实际根路径，
在写入或启动前核验其摘要及无链接路径；摘要匹配不代替目录状态检查或操作批准。

1. **预览**：检查目标版本支持所需字段/命令、目标目录不存在、端口不被占用；
   声明隔离边界、停止方式和预算。既有目录即使同名也拒绝覆盖。
2. **安装**：在批准的新根内建立私有目录和必要文件；以封闭环境调用官方
   `setup --baseline --json`（2026-10-10 用户批准调整首个 Agent 注册方案）：先由
   批准工件生成唯一 `agents.entries` 配置，再让官方基础初始化建立会话目录。
   不使用会保留默认 main 的 `agents add`，也不启用引导向导、服务安装或认证配置。
   HOME、状态、配置、Agent 目录全部归属新根，不继承宿主凭据。
   用官方列表和实际文件核验 Agent ID、工作区、模型及权限；不成功则保持未激活。
3. **激活**：先启预算代理，再启动仅监听回环的独立 OpenClaw 网关；不用 LaunchAgent、
   不自启动、不安装插件、不绑定外部渠道。启动失败关闭本次自有进程，保留失败证据。
4. **使用**：入口必须来自本次网关实际地址并绑定目标 Agent/会话；不能只验证页面
   能打开。鉴权 token 留在本地私有状态和受控连接流程，不写进交付文档或 URL。
5. **停止/恢复**：只停止自己持有并核验身份的进程，不按通用名称杀进程或释放他人端口。
   重启复用已核验的包、状态及会话；遇到未知残留或身份漂移拒绝自动接管。

绑定复用现有 install/activation/runtime 批准与证据体系的适用部分；其中 Linux
专用执行器不被调用或伪造为成功。新分支须有独立的可验证结果与认证范围。

### 安全边界

这是同一用户下的进程和状态隔离，不是操作系统安全沙箱。拒绝路径穿越、符号链接、
意外覆盖、混用状态和包摘要漂移；工具权限必须由运行时实际生效。
不声称抵御恶意同 UID 进程并发篡改运行时或读取该用户内存/私有文件。
该限制只属于新本机分支，不改变旧 Linux 事务、进程约束或证据的含义。
模型与材料均不能授予安装/工具权限；workspace 提示词不是安全边界。

## 模型、预算与输入处理

- 沿用已选 DeepSeek 模型引用及项目累计 CNY 100 上限；读取账本引用和脱敏余额，
  不另建可重新花费 100 元的账本。新演示授权必须精确绑定这一个预算。
- 凭据通过既有受控运行入口仅在内存中使用；Codex 不读取、展示或复制 `.env`。
  OpenClaw 只获得本机代理凭据，不获得真实 provider key。
- 新增的薄代理只负责输入验证、共享预算预留、一次上游请求、受限错误与计数；
  不增加模型规划循环、第二次“润色”请求或新的聊天 UI。共享预算机制从既有实现
  最小提取复用，不复制预算政策或重新初始化旧额度。
- 原生 provider retry 配置为 0、fallbacks 为空，代理返回禁止重试提示；必须用
  模拟 429/500/超时和真实原生入口验证上游请求数，不能凭配置声明有效。
- 代理在调用前持久记录已验证请求的规范摘要和预算预留；同一请求重复投递拒绝
  再花费。失败、崩溃或结果不明保留占用，不自动续跑或退款；重启不能清空去重记录。
  去重只存摘要/状态，不复制聊天正文到诊断或发布证据。
- 最新用户文字为空或超过 8,000 Unicode 码点时，在预算预留前拒绝。只接受已验证
  原生请求结构；不能用模糊截取去剥除用户正文，也不能静默截断。
- 保留原生会话历史以支持纠正和追问，不照搬 Course Wiki 的“只投影最新提问”行为。
  同时限制完整请求大小与输出 token；上下文超限明确失败，不自行付费压缩会话。
- 不调用工具、检索、记忆插件或后台任务。有效工具集合必须为空；观察到工具调用、
  隐藏模型请求或无法约束的自动重试，立即判失败，保留未交付状态。

## 验收与交付标准

先 TDD 验证工件与边界，再用真实 OpenClaw 加模拟上游验证原生兼容；最后才在精确
运行授权及原累计预算内，用合成会议文本做真实模型验收。

| 必须通过 | 验证内容 |
| --- | --- |
| 正式创建链 | 从需求经批准工件生成并注册新 Agent；无人工预置成品旁路 |
| 原生入口 | 用户可打开、鉴权、选到正确 Agent、发送消息并看见最终回复 |
| 内容质量 | 摘要/决策/行动项/未决问题齐全；不编造负责人、日期或事实 |
| 多轮与隔离 | 同会话纠正生效；新会话不串会；重启后原生 Agent/保留会话可用 |
| 无工具与注入 | 材料中的恶意指令不会触发工具、读取秘密或扩大权限 |
| 输入失败 | 空/超长/未知结构在花费前拒绝，不静默截断 |
| 模型失败 | 429、500、超时、断流可见；无自动重试扣费和假成功 |
| 预算与恢复 | 共享额度、并发预留、重复投递、崩溃重启均不能多花或重置额度 |
| 状态保护 | 旧网关、旧 Agent/会话不变；端口冲突或注册失败不覆盖现有状态 |

全量与聚焦测试分开报告：相关 Stage 2 回归、全新 Node 20 owned evidence 与消费者、
`npm run check`、`git diff --check`。运行证据记录工件摘要、目标版本、用例 ID、
结果和预算计数，不保存原始会话/provider payload。领域样例通过不等于通用质量认证。

最终交付只有四项：Agent 名称、已实际验证的原生入口、试用示例、停止/恢复说明。
任一关键验收失败则报告部分完成与具体缺口，不邀请用户替我们发现已知错误。

## 2026-10-09 已批准补充：独立批准消费记录

用户批准实现独立于 Agent stateRoot、互不包含的本机记录目录；此批准不授权真实
初始化、安装、激活、模型调用或提交。保留既有 authorityRootBinding 字段，native
分支改为封闭的 agentmo.native-authority-binding.v1：根路径摘要、随机身份文件
摘要，以及目录/身份文件/消费日志的 device、inode、birthtimeNs。无明文主机路径。

显式初始化只能创建全新目录；安装消费只能打开精确已绑定的记录，绝不自动重建。
消费前验证全部普通/逐项敏感/冲突批准及真实当前时间；所有类型共享 nonce 去重。
消费集合以一条只含摘要的记录追加到私有日志，排他锁和 fsync 完成后才返回。
失败后保留不确定锁或残缺日志，禁止自动续跑；缺失、替换、链接、权限漂移、
非规范路径（包括末尾斜杠、父路径或记录根大小写别名）、重复使用或超过 1 MiB
日志上限均拒绝，不清空历史来恢复。

此机制防止正常删除 Agent 根或进程重启重置已用批准，不是 OS 隔离；拥有同一
UID 的人主动回滚完整历史不在本地机制的可信边界内，需要外部授权服务才可抵抗。
生命周期安装入口尚未接入时，不得把库级消费记录称为已安装或已激活证据。
