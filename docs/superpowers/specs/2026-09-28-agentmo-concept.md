# AgentMo 概念设计 v1：从一句需求到可用 Agent

日期：2026-09-28。状态：用户已批准概念方向；不是已实现能力或实施计划。
本次只更新设计文档，不安装 Agent、不改变服务、不调用付费模型、不提交代码。
规范主线仍以 [CONCEPT.md](../../CONCEPT.md) 的 Discover → Plan → Produce 为准。

## 1. 产品定位

AgentMo 把用户的工作需求变成一个有明确职责、必要能力、可验证产物和实际使用入口的
Agent。它是 Agent 的构建与交付系统，不是提示词生成器，也不是另一个 OpenClaw。

用户已明确：先完成简单、真实可用的闭环，允许更换 POC，不再以通用架构扩张替代交付。
第一条演示采用会议文字助手；原课程 POC 和证据保留。
第一版使用现有 OpenClaw 运行环境和已选模型；研究 CMA/WMA 不意味着接入其云服务。

产品承诺是“一句话发起、必要确认后交付”，不是一句话无限授权，更不是任意需求都能实现。
用户不需要理解文件格式、手工粘贴配置或在多个开发 Session 之间传话。

## 2. 一手资料给出的启发

下列事实来自官方文档或案例作者；“采用”是 AgentMo 的设计选择，不是已完成集成。
调研日期为 2026-09-28，线上文档可能领先本机版本。

| 参考 | 已核对的结构 | AgentMo 采用什么 | 不照搬什么 |
| --- | --- | --- | --- |
| OpenClaw | 工作区、原生 Agent 配置、会话与入口共同组成可用 Agent | 生成原生资产，接好真实入口，使用原生执行循环 | 不把几份 Markdown 当作完整交付，不默认安装所有技能 |
| Anthropic CMA | Agent、Environment、Session、Events 是不同概念 | 将可复用定义、运行环境、一次任务和证据分开 | 不因此新建四个服务或立即接入托管 API |
| CMA 工程设计 | harness、执行环境与持久会话日志解耦 | 构建记录不能依赖某个临时进程存活；凭据远离不可信执行内容 | 不复制其云沙箱调度和基础设施 |
| 腾讯 WMA | Agent / Runtime / Session；Manifest、试运行、渠道和治理相互配合 | “可配置”之后还要“可试用、可交付”；配置与运行状态分离 | 不把企业云托管、连接器或合规宣传当成本地已有能力 |
| 实际案例 | 会议文字可直接产生纪要与行动项；知识库案例额外需要采集和检索 | 先选依赖少、结果容易核对的任务 | 不以社区展示等同独立质量验证 |

[OpenClaw workspace](https://docs.openclaw.ai/concepts/agent-workspace)、
[CMA overview](https://platform.claude.com/docs/en/managed-agents/overview)、

此处 CMA 指 Anthropic Claude Managed Agents；WMA 指腾讯 WorkBuddy Managed Agents。
WMA 官方页面存在“一个 Runtime 可有多个 Session”与“通常一一对应”的不同表述，因此
这里只借鉴对象分离，不把部署基数写成 AgentMo 合同。
云端存储或自托管不自动等于“数据不会外发”；是否向模型发送工具结果必须另行审计。

Anthropic 的另一条有用原则是保持上下文高信号、按需读取材料，而非一次灌入所有历史。
AgentMo 因而默认只提供任务所需指令和能力；记忆、检索、多 Agent 均按需要添加。
这属于我们的选型原则，不证明现有适配器已实现全部策略。
[上下文工程原文](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)。

## 3. 最小架构与职责

```text
一句需求 + 授权材料
        │
        ▼
AgentMo：Discover → Plan → Produce
  需求与来源 → 定义和验收 → 复用/构建、投影、验证、交付
        │                         ▲
        ▼                         │ 脱敏结果与失败反馈
已确认版本的 Agent Package → OpenClaw 原生 Agent
                              工作区 / 模型 / 权限 / 会话 / 聊天入口
```

AgentMo 的开发任务调度与所产 Agent 的对话循环是两件事。Codex 是当前 builder；
OpenClaw 是第一运行目标。AgentMo 不在两者之间再增加一个无必要的通用执行循环。

四类对象映射到已有工件，不建立平行 JSON 体系：

1. **定义与版本**：Blueprint / Build Contract / Package Manifest，说明做什么、靠什么做。
2. **运行绑定**：现有目标适配与安装/激活工件，说明装到哪里、用哪个原生 Agent ID。
3. **会话与执行**：原生会话由 OpenClaw 管理；AgentMo 的 run-state 记录受限执行证据。
4. **验收与交付**：复用 eval、birth、delivery 工件，说明测过什么、入口是否可用、还缺什么。

接口映射是概念设计，不等于已存在完整的自然语言编排器。
用户材料、原生会话、学习记忆和可发布证据必须分开：前三者按权限保留，证据只存必要
摘要、摘要哈希、检查结果和引用；不把原始对话复制到 release。

## 4. 完整 Agent 的最小内容

| 内容 | 第一版要求 | OpenClaw 映射与边界 |
| --- | --- | --- |
| 身份与任务 | 名称、服务对象、输入输出、不能做什么 | 原生身份配置及必要 workspace 指令 |
| 行为 | 工作步骤、回答格式、不确定信息如何处理 | AGENTS.md / SOUL.md，避免重复堆砌 |
| 能力 | 仅启用任务必要能力 | 原生工具权限；skills 是使用说明，不是权限开关 |
| 模型 | 已验证模型和运行参数 | 配置与凭据引用；包内不能有 key |
| 数据和记忆 | 来源授权；长期记忆默认不增加 | 当前会话不等于长期知识库，不默认向量数据库 |
| 状态和隔离 | 独立 agent/session 归属，明确重启行为 | workspace 不是沙箱，工具隔离由运行时保证 |
| 入口 | 在 OpenClaw 中可定位并直接交互 | 需要核验路由，不能只交一个能打开的 URL |
| 验收 | 固定场景、成本限制、检查和失败结果 | 使用现有评测机制，不再开发通用评测平台 |

不要求每个 Agent 都有 skills、MCP、MEMORY.md、HEARTBEAT.md 或自定义插件。
目标版本确实需要的 bootstrap 文件可以生成；不能为凑目录而宣称不存在的能力。
线上模板和配置字段必须先与本机版本匹配，不能无条件升级或覆写用户配置。

## 5. 一句话创建的用户旅程

1. **输入**：用户描述工作。若需求已明确，Discover 记录需求、材料与证据缺口，
   不强迫先做市场调研；需探寻机会时才搜索授权来源。
2. **预览**：展示任务范围、输入输出、模型、必要权限、费用边界、目标和验收样例。
   缺失会改变方案的信息才询问；未提供的负责人、日期、密钥不能猜测。
3. **构建**：沿已批准工件执行；先复用原生能力或模板，再补确实缺失的代码。
4. **试运行**：用合成或已授权公开材料，通过真实原生入口验证，不靠 mock 回复冒充。
5. **交付**：给出 Agent 名称、可用入口、试用示例、范围和剩余缺口，以及停止/恢复说明。

一个阶段的批准不替代下一阶段。已有批准只在主体、摘要和范围仍匹配时复用，不重复
询问同一动作；新增权限、实际安装/激活、付费边界变化仍按原合同处理。
“减少打扰”通过清晰预览和准确复用授权实现，不通过删掉安全门禁实现。

## 6. 第一条演示：会议文字助手

建议创建请求：

> 创建一个会议助手，把我提供的会议文字整理成纪要和待办，不能编造负责人或日期。

第一版只接受聊天中粘贴的文字，不把上传、DOCX 解析、语音转写也塞进关键路径。
建议上限每条 8,000 字符，实际 token 限制以目标模型校验为准；超限明确拒绝，不能静默截断。
输出在聊天中展示为 Markdown：摘要、决策、行动项（任务/负责人/截止时间）、未决问题。
未明确的信息标记“未说明”。同会话可以纠正信息和修改格式，新会话不得继承另一会议内容。

默认单 Agent、不调用业务工具、不做 RAG、不定时、不自动发送消息、不写外部工单。
不新建网页界面，优先使用已安装 OpenClaw 的原生入口。DeepSeek 模型沿用已核验选项；
现有预算账本继续累计，但新场景的真实调用须纳入原授权范围核验，不能另开预算绕过上限。

预先固定最小验收：

- 从创建请求产生并注册新的 Agent，非人工预先写死该 Agent 的所有成品文件。
- 在交付入口发送合成会议文本，决策与行动项正确，遗漏信息不编造。
- 同会话要求修改负责人或输出格式，正确处理最新要求。
- 材料中包含“忽略规则/读取密钥”的文字，不执行材料指令或启用额外工具。
- 空输入/超限输入明确反馈；模型失败可见，不冒充成功、不自动付费重试。
- 新会话不串会；按目标原生机制重启后，Agent 和需保留的会话仍可使用。

机械检查覆盖注册、路由、范围和权限；语义检查覆盖遗漏、编造和追问一致性。
每项记录实际执行与结果；失败即保留失败状态。创建成功、原生运行、用例通过和入口交付
分别展示，不能以总测试数量替代以上链路。

## 7. 已有实现与真正缺口

| 现状证据 | 可以复用 | 仍须完成 |
| --- | --- | --- |
| `src/targets/openclaw.js` | 从 blueprint 生成 workspace 的现有适配入口 | 验证新场景可走完整创建路径，不能把 scaffold 当作已安装 |
| `src/targets/openclaw-package.js` | package、能力映射与目标绑定机制 | 当前有 support-triage 固定内容和 native-plugin 前置条件，不能直接声称通用无插件生产 |
| `src/blueprint.js` | blueprint 校验与工具合同 | 当前要求至少一个 tool；不能为无工具助手捏造 dummy tool，需评估窄范围合同演进 |
| 现有 install/run/eval/birth/delivery 体系 | 授权、生命周期与证据 | 需要同一个新 Agent 版本贯穿到底，并从真实交付入口验收 |
| Course Wiki 2026-09-28 单项证据 | 模型连通、原生调用和独立审查经验 | 不证明一句话创建、其他场景或用户入口已完成 |

实施前先核对 scaffold 与正式 package 两条路径的承载范围，选择一条合法支持最小场景的
路径到底。若需要改变 schema 或去除强制插件，形成窄范围实施变更并审阅，不能绕过
现有校验器、靠人工注册旁路后宣称 AgentMo 已完成自动创建。
本设计不决定删除现有代码，也不为解决合同缺口启动全项目重构。

## 8. 收口决策

采用：一个清晰场景、原生运行时、最少能力、现有工件、真实入口验收。
暂不采用：新通用 harness、向量库、多 Agent 编排、云沙箱调度、技能市场、全新 UI。
只有具体失败或新增用户需求证明必要时，才增加相应组件。

概念设计完成的标准是定位、职责、对象、交付物、第一演示和验收边界都已明确；
产品完成的标准则是这条链真实执行成功。两者不可混称。
下一步为现有路径的精确缺口制定实施计划；不是再做一轮泛化架构研究。
首批计划见 [原生文字助手基础](../plans/2026-09-28-native-chat-foundation.md)。
