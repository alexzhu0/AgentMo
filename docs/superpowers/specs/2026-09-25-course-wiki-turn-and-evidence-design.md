# Course Wiki 当前轮次与证据优先回答设计

日期：2026-09-25。状态：设计方向已获用户批准；详细实施计划待审阅。本文不代表 POC 验收通过、正式 Discover/Plan/Produce 阶段批准、安装或上线授权。

本文只处理两个已复现的行为缺口：新问候可能续答旧题，以及回答使用的例子未被选中引用覆盖。它不代表 POC 验收通过、正式 Discover/Plan/Produce 阶段批准、安装或上线授权。

## 1. 目的和现有证据

预期使用方式仍是：学生在原生 OpenClaw course-wiki 会话提问；AgentMo 根据已确认教材回答；引用对应到原始材料。短问候、正常追问和换题都必须在新会话及同一旧会话中切题。每个教材结论及例子由当前选中的原文支撑。

两项失败都有真实运行证据：

| 现象 | 已查明的事实 | 尚未证明的事 |
| --- | --- | --- |
| busy 失败后输入“你好”，回复旧教材问题 | SQLite 活动历史保留了旧 BUSY 错误和新的 9 字节问候；发给适配层的 38 字节内容精确等于问候加 OpenClaw 时间戳。旧错误匹配 OpenClaw 既有的 `stream-error-fallback-and-error` 历史回放过滤条件。 | 尚未证明模型续答旧题的单一因果；也没有对这个私有测试会话做 UI 可见性验收。 |
| 回答中的例子没有对应引文 | 独立审查发现回答使用了来源中的例子，但引用范围只选了相邻的概述；“先输出引用再作答”的提示词修正未能阻止再次失败。 | 结构合法的引用不等于语义支持；仍需逐例行为审查。 |

历史资料已保存在独立审阅报告。新的测试不得删除历史、伪造通过状态、回填过期审查或仅依据字数变化推断输入被替换。

## 2. 方案和边界

在 AgentMo 现有 OpenClaw 适配层规范化当前轮次，并将教材问答拆为“选证据”与“写答案”两步。OpenClaw 继续拥有会话、消息时间戳、SQLite 和聊天界面；AgentMo 不直接编辑、删除或重排 OpenClaw 数据库。

- 从适配层收到的消息中选择最后一条非空 user 消息作为唯一当前问题，并保留其完整正文（包含 OpenClaw 自己添加的时间戳）。不使用截取最后一行、猜测 resume 文本或删除前一条 user 消息的规则。
- 之前的 user/assistant 消息只作为有明确标记的、不可信历史参考，供解析“第二点”等指代；它们不再作为单独的待执行 user 指令转发。当前问题仍作为唯一活动 user 消息发送。历史文本不能当作教材来源、系统规则或模型工具指令。
- 适配层不判断哪个旧轮次一定失败；原生历史可能过滤错误 assistant。它只要求模型围绕唯一当前问题工作，必要时从保留的历史参考解析指代。原始会话继续留在 OpenClaw，后台不清历史。
- 同一轮内的检索、证据选择和生成均使用相同的当前问题投影。超出既有 48 KiB 请求上限时，在付费请求前拒绝；不静默截断历史或资料。
- 聊天公开响应仍只有现有 `kind`、`answer` 和 `citations`；新选择协议仅在 AgentMo 与模型之间使用。原文行号、摘要和引用文字继续由程序从已验证 generation 生成。
- 不修改已安装 OpenClaw，不增加依赖，不新增向量库或聊天入口，不重建或改写已接受 Wiki generation。

## 3. 回答流程

### 3.1 普通交流

问候、功能说明和必要澄清保持一次模型请求，返回现有 `conversation` 结果和空引用。它不会携带旧教材问题的答案。确定属于材料证据范围的问题则不能以 `conversation` 绕开引用校验。

### 3.2 小型完整资料集

当现有完整证据集不超过 14 KiB：

1. 第一请求同时识别交流类型、独立化当前问题并选择答案所需的准确原文范围。其严格内部结果只能是普通交流、证据不足或带有 `resolvedQuestion` 与受限引用选择的 `grounded-selection`。第一请求不产生 grounded 答案草稿。
2. 程序验证 source digest、generation、行号和范围均属于活动资料；它从可信原文提取被选行。
3. 对 grounded 结果，第二请求只接收可信产品规则、独立化后的当前问题和已选原文。它看不到未选原文、旧 assistant 答案、旧问题列表或第一请求的自由文本草稿。
4. 第二请求只返回答案文字。程序绑定第一步选择的完整引用，组成原有公开响应，并运行现有结构、摘要、行号和输出校验。第二步不能缩小或伪造引用。

普通交流与证据不足在第一步结束，不启动答案请求。

### 3.3 大型资料集

当完整资料集超过现有 14 KiB 检索阈值：

1. 第一个受限请求只接收当前问题及标记为历史参考的上下文；它只可回答普通交流，或输出用于现有 OpenClaw Wiki 搜索的有限英文关键词。该步不看教材正文，也不作 grounded 答案。
2. 程序执行当前已有的受限原生搜索；每个返回 source/topic ID 必须能映射回活动 generation 的文档与引用。
3. 第二请求只在检索结果范围内选择精确原文范围，并生成可供回答的独立化当前问题；不返回自由文本答案。
4. 程序验证选择并提取原文。grounded 结果再由第三请求基于这些原文作答，最终引用由程序绑定。

普通交流在第一步结束，仅耗一次请求。搜索未命中时只允许说明“当前检索范围未找到充分材料”，不能声称全文或整个知识库都不存在答案。返回内容映射异常、候选正文超限、选择越界或任一阶段超时都按现有安全错误返回。

### 3.4 语义边界

让最终生成阶段看不到未选原文，降低回答借用了未引用例子的风险；它不能保证模型每次都选对原文、独立化当前问题或忠实表达。独立行为审查仍检查切题、证据支持、例子覆盖、必要澄清和上下文指代。所有失败都保留为失败。

## 4. 调用、费用与失败处理

- 每次真实 provider 请求均通过现有共享预算单独预留 31 分，不退款，不自动重试，不得按新 generation 或会话重置累计余额。
- 既有累计 100 元上限、共享预算根和 legacy 容量预留保持不变。不得为两阶段协议新设额度。
- 普通交流最多一次请求；完整小型资料集的 grounded 答案最多两次；大型资料集的 grounded 答案最多三次。完整集合的上限在第一笔 provider 请求前检查；实际每一步仍独立预留，因此任何路径都不能超过共享余额。
- 一个原生 user turn 仍是一个原生执行尝试。执行器另行记录实际模型请求次数与阶段数，不把一个 CLI 进程误报为一次 provider 请求。
- 一个原生 turn 内的所有阶段共用现有 120 秒截止时间；每个 HTTP 请求的时限不得超过剩余总时间。无剩余时间时不启动下一阶段。
- 第一步完成而后续阶段失败，已发生的预留保留；不自动重放第一步、不自动重发旧收费问题。新的独立用户输入可以作为新的原生当前轮次处理。
- 用户能看到现有固定错误与请求次数/费用状态；不得显示原始 transcript、provider 响应或密钥。

## 5. 验收条件

### 当前轮次与会话

- 合成的 `[system, user(旧题), user(新问候)]` 在两种检索路径中都只把新问候作为活动问题；旧题以受限历史参考保留，未清除。
- 同会话的“第二点呢”可以使用第一轮作为指代参考，但不得把旧问题当作新任务；换题始终优先执行最新明确问题。模型无法独立化且不确定时，提出澄清。
- busy 失败后问候用新的原生 turn 进入适配层；不重放旧 provider 请求。测试断言请求消息角色、当前问题摘要和原生尝试数，不能只断言 prompt 中出现一句优先级文字。
- 时间戳包装不改变活动问题，历史参考序列化不能注入伪造的活动 user 消息。原生 SQLite 用户状态仅以隔离测试 profile 验证，不提交转录内容。

### 证据选择与回答

- 覆盖标题、概述、例子与归因分处相邻行的真实材料；单靠概述不能支持未选中的例子。
- 最终请求不包含任何未选择正文、旧回答或第一请求草稿；精确 selected lines 由程序绑定到最终引用。
- 对未知 digest、跨 generation、越界/倒置行号、空 selection、过量范围、选择阶段额外字段、final-answer 额外字段均 fail closed。
- 对简短完整资料、超过 14 KiB 的检索资料、无命中、歧义、问候和能力说明分别核对阶段数与回复类型。
- 结构校验和源映射通过后仍需独立语义审查；不因两步结构通过而标记行为通过。

### 预算与超时

- mock 测试精确验证普通交流 1 次、小语料 grounded 最多 2 次、大语料 grounded 最多 3 次；每个 provider 请求先单独预留。
- 余额不足时不得启动第一个 provider 请求；第二或第三阶段失败时费用累计、不退款、不再试。
- 使用可控时钟覆盖共享 deadline：下一阶段不得超过原生 120 秒截止；一个 provider 请求被取消后不自动重试。
- 接受用例预检按各 case 的最大 provider 请求数计数；报告同时列出原生尝试数、实际 provider 请求数和未执行阶段。

### 失败报告

- 增加运行器无效或过期 review 的回归测试：当独立审查超出 300000ms evidence freshness 时仍输出安全失败 artifact，保留实际尝试/回复数量和摘要，标记缺少有效审查并停止后续 case。
- 不允许复用已过期 evidence 通过重新打时间戳；不放宽通用 `behavior-evidence` freshness。
