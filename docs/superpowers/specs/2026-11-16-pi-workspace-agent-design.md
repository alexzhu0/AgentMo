# AgentMo 下一版：Pi 授权资料、领域 Skills 与成果文件

日期：2026-11-16。状态：用户已选定最小方向并要求一并编写规格和离线实施计划；本文件为待审阅规格，不代表已实施或获得任何真实运行批准。

## 1. 目标、范围和选择

交付一个本机单用户 Pi CLI Agent：接收明确任务，按需读取已授权文字资料，按随包领域 Skill 工作，产出带来源引用的 Markdown 文件，支持在同一版本和资料快照下追问及停止后继续。继续使用 Discover → Plan → Produce；AgentMo负责生成、权限、预算与交付，Pi负责原生provider、工具循环和SessionManager。

用户在本轮明确选择复用Pi原生循环、授权读取、领域Skills、成果输出，并要求规格和计划一起完成。因此不再分拆文档编写批准。此前方案B“宿主一次性拼入全部资料、单次回答后保存”改动更少，但缺少按需工具往返，本轮采用方案A的有界原生工具任务。大型平台、另一套Agent循环和升级SDK均无必要。

边界：一个Agent、两份.txt/.md输入、一份纯文字SKILL.md、两个工具read/write、一份新的report.md。本轮不增加bash/edit、任意目录搜索、图片/PDF解析、MCP、联网搜索、多Agent运行、浏览器产品、长期记忆、自动压缩、后台模型请求或自动重试。协作会话仅用于开发分工，不是生成Agent的多Agent功能。

代表性离线夹具由实施者选为“项目资料简报”：根据两份合成资料生成结论、证据和信息缺口三部分。它是通用能力的测试载体，不把AgentMo固化成报告专用工厂，不恢复会议助手。真实业务资料在未来具体运行预览中由用户授权。

## 2. 用户体验与交付

1. Codex从需求和授权来源生成领域Skill、输入策略、输出约定，进入现有Plan与Produce链。用户不手拼摘要或修改安装目录。
2. 沿用agentmo pi-chat。新增/workspace入口：展示最多两份明确授权文件的候选列表并由用户选择，或接收两条明确相对路径；捕获输入内容与身份。目录枚举只覆盖显式source-root的直接普通.txt/.md候选，不递归、不开正文、不过滤后自动选中。
3. 预览展示Agent/版本/会话、实际任务、输入文件内容与摘要、Skill、将随历史再次发送的资料范围、输出绝对位置、调用/费用/时间上限。拒绝或过期不激活、不预留、不生成成果。
4. 一次确认只授权这一次有界任务。工具输入只能从已确认资料和Skill中选择，输出只能暂存到预览指定文件；Pi可在上限内决定调用次序。工具中间参数不要求再次弹窗；超出已确认范围立即终止。真实安装、激活和模型验收仍分别提供具体预览，不能以本规格替代。
5. 结束时显示最终说明、实际模型请求/本地预留、成果路径、来源摘要和停止结果。追问使用新的任务预览和新的成果子目录；已有成果不覆盖。
6. 保留已有普通文字、/file、/sessions、/use、/new和退出行为；未声明新能力的Agent继续走原文字路径。新能力Agent的每次有成果任务固定绑定资料快照；变更资料或Skill需要新会话/版本适用的精确预览，禁止静默迁移历史。

本版只交付Markdown，不另加格式转换器。CLI仍是薄入口，现有路径/摘要装配由Codex完成。

## 3. 明确的容量和执行上限

以下是本规格的工程默认值，不是新增真实费用授权。后续预览可收紧，不可扩大。

| 项目 | 固定上限或行为 |
| --- | --- |
| 输入 | 1–2份UTF-8普通.txt/.md；每份4096字节，合计8192字节 |
| Skill | 恰好1份纯文字SKILL.md，最多4096字节，随包固定摘要 |
| 任务文字 | 沿用8000 Unicode码点；实际完整请求仍须满足wire上限 |
| 模型请求 | 每任务最多6次，包含工具循环所有中间请求及最后回复 |
| 工具调用 | 每任务最多8次；read允许重复且计数，write恰好最多1次；按原生顺序串行执行 |
| 输出 | 一个report.md，最多8192 UTF-8字节；一次write只暂存，最终通过后发布 |
| 上游 | 固定MiniMax-M3/minimax-cn、SDK1.2.0、thinking off；每请求max_tokens=2048 |
| 请求限制 | 完整序列化请求48KiB、最多32条messages（按既有system计数约定），包含工具schema与结果；不截断历史绕过 |
| 时限 | 整项工作10分钟含启动/I/O/模型；每次供应商请求最多90秒且服从总期限；自有清理另最多300秒 |
| 重试 | 0自动重试、0自动重启、0后台调用；失败停止，不补跑 |
| 本地预留 | 每次实际尝试上游前沿用31分保守预留；整任务最多186分。使用前必须证明新wire仍符合原输入/输出成本包络，不能因tools增加而漏算 |
| 原真实账本 | 累计5053分（50.53元）/35笔，10000分上限；不退款、不重置、不创建替代真实账本 |

在账本仍为5053分时，单任务理论累计上限5239分；这是静态计算，不是运行报价或批准。若离线成本包络复核不能支持31分，停止生成可执行预览、给出修正后的具体费用，再由用户批准；不自动提高额度或更换模型。本地预留不等于供应商账单。

即使还有模型次数余额，只要发生网络、工具、协议、会话或文件错误，本任务终止。未用额度不转给下次任务。预算不足以覆盖预览全部上限时拒绝开始；每个实际请求还要原子地复核原全局账本和本任务余额。

## 4. 最小合同扩展与版本兼容

沿用execution_profile=native-chat、native_runtime=pi以及minimax-m3-cn-v1作为外层运行选择；用可选pi_workspace显式选择新能力，避免把旧包默认为有工具。

pi_workspace在UserNeed、Design Plan和Blueprint中逐级传递，Build Contract新增同名可选顶层字段，精确相等并进入所有原有摘要/批准绑定。字段：
- schemaVersion固定agentmo.pi-workspace.v1。
- inputPolicy固定扩展名txt/md、文件数2、单文件4096、合计8192。
- skill包含name、description、body（完整SKILL.md文字）、digest；name为小写slug，description不超过256字符，body整体不超过4096字节。digest对原UTF-8字节计算；名称和描述必须匹配正文frontmatter。无脚本、附件、动态安装依赖或额外相对文件。
- outputPolicy固定report.md、markdown、8192字节、overwrite=false。
- limits固定本规格第3节的请求/工具/时间/费用边界；不由模型或环境变量改写。

实际本机绝对路径和资料正文不进入可发布工程包；输入清单及内容快照只属于每次私有任务。Skill是用户批准的可发布领域方法，须先通过现有persistability检查。缺失pi_workspace时旧所有字段、零工具规则、测试夹具与输出字节保持；不采用“解析失败回落旧模式”。

Build Contract的specification、resources、permissions、evidenceObligations和traceGraph必须准确反映Skill与两个工具；不得只新增字段而仍写skills disabled/no-tools。采用原有工件和批准体系，不新增平行批准系统。

Pi投影在原六文件外增加workspace-policy.json与skills/<name>/SKILL.md。agent.json明确声明read/write及pi_workspace摘要，mcp仍false；安装精确清单增加两文件和skills两级目录，旧六文件安装继续适用。实际清单从已准入包推导，仅接受这两类额外路径，禁止开放任意扩展文件。所有新文件参与archive、carrier admission、source closure、安装回执与激活绑定；只读激活只检查资源装配和零后台请求，不暗中读用户资料或写成果。

## 5. 授权资料读取与Skill加载

确认前，父进程复用现有CLI文件安全策略捕获实际输入字节、原路径、文件身份、摘要和行数；拒绝.env及其它秘密/控制文件、受管状态、符号链接、硬链接、非常规文件、非法UTF-8和超限内容。检查路径发生在打开正文之前，不因错误回退到宽松readFile。

确认时重新校验输入身份和摘要，变更则使预览失效。执行只使用已确认内存快照；模型按需read时不会重新读被替换的原路径。文件全文允许发给M3的事实必须在预览中明确，资料不是工具权限来源。

模型只看到固定逻辑路径sources/1.md、sources/2.md、skills/<name>/SKILL.md及output/report.md；实际路径映射由父进程控制。读取结果含来源ID、摘要和行号。read只接受这三个已批准入口，不解析任意绝对路径、..、~、URI、glob或额外文件。行号按原文本换行划分；范围引用必须对应实际已read的资料。Skill内容单独标记为工作方法，来源资料中的指令只作为资料。

使用Pi1.2.0原生Skills/扩展接口；从固定包加载一份Skill与受信工具定义。既有自定义ResourceLoader改为返回明确资源，不扫描HOME、祖先AGENTS.md或全局.pi目录。Skill名称、描述、正文及“缺证据时列缺口、对结论给出处、写入成果后简短说明”的领域流程来自包。工具通过Pi扩展registerTool接入；不得执行资料中的JavaScript或第三方扩展。

完成任务前必须能证明该Skill正文已进入当前原生上下文，且被引用资料确已通过read提供。允许复用同一会话内、同一资料/Skill摘要的成功历史读取记录；新会话不能借用它们。新请求预览应显示这部分历史授权范围，不因复用历史而绕过wire/费用限制。

工具execute经既有父子通道交给父进程处理：read返回批准的内存快照，write暂存文本与引用。请求绑定task/session/toolCallId，重复、未知任务和取消后请求拒绝；Pi仍负责何时调用工具及何时继续推理。无新的本地HTTP服务或自制模型while循环。

## 6. 原生循环、协议与任务预算

当前pi-sdk的单assistant、只接受end_turn、无工具事件限制仅适用于旧文字路径。新路径允许中间assistant/toolCall/toolResult及tool_use结束，最后必须有且只有一个成功end_turn最终回复。Pi负责SSE解析与工具调度；AgentMo只校验当前模型、允许的消息/工具、上限、失败和最终结果，不再假定每任务只有一次message_start。

代理仍由父进程持有供应商密钥，SDK仅拿本地不透明任务凭据。新任务凭据绑定一次确认的taskDigest、会话、资料/Skill摘要及上限，最多用于6个顺序请求；旧凭据仍只能一次。每次原子claim一个新requestIndex和requestDigest，再预留31分，发送一次。拒绝并发、超限、结束后继续、旧任务重放；同一wire摘要可能是一次新请求也可能是网络重发，不按摘要猜测：由原子序号和已消费任务状态判定，失败后任务立即关闭。

校验首个请求包含批准的实际任务和系统/Skill资源；后续请求必须是同一原生会话的合法扩展。检查tool_use ID唯一、名称仅read/write、参数匹配定义，tool_result对应已执行调用且内容与宿主记录相同；拒绝模型自行伪造未读资料或写入回执。限制tool schema、完整body、消息数、工具结果与历史总量，在预留及发送之前完成。

每请求记录claim/reserved/sent/终态及耗费，每任务记录批准上限、请求计数、工具计数、最终回复和成果状态。原全局预算reserve原子实现继续复用；不得把6请求合成一笔31分。失败已发生预留保留，不退款；崩溃后未终结任务标interrupted并关闭，不自动继续剩余步骤。

上游TLS1.2专用传输、证书校验、重试关闭和敏感信息隔离保持。密钥仅未来获批既有父运行器在内存加载，本轮助手、工程与审阅均不读取其值。

## 7. 成果发布、会话和可验证证据

write工具只允许output/report.md，参数是content和citations数组。每项citation为sourceId/startLine/endLine；正文使用同一来源标记。宿主检查文件大小、格式、引用存在/行范围/确已读取；至少一个实际来源引用，资料不足可输出“信息缺口”，禁止假造事实。机械检查只证明来源对应，内容是否忠实仍由独立内容评审确定。

write先保存在本次私有attempt的暂存区，返回staged及摘要；不能向模型宣称已发布。最终原生回复完成、会话耐久保存、预算/工具状态检查通过后，父进程把同一字节发布到预览中的独占新目录<output-root>/<task-id>/report.md，再保存仅含元数据的成果记录。每次任务输出新目录，预览前该目录必须不存在，不能覆盖输入、旧成果或旧失败。

output-root须为用户明确指定、当前用户拥有的私有普通目录，拒绝链接和身份变化；其路径与输入、Agent安装/状态、批准存储、预算目录、仓库控制目录及秘密目录不得重叠。使用现有安全文件写入组件，发布采用无覆盖方式，文件0600、任务目录0700，文件和目录同步后再报告。若发布与结果记录之间崩溃，保留实际文件和attempt，标publication-uncertain，不谎称未写入，不自动删除、覆盖或补发。

沿用现有单用户可信宿主边界：目录身份复核、NOFOLLOW和无覆盖写入用于拒绝可观察的替换与越界，不宣称抵御同UID恶意进程持续竞争改名或提供OS级沙箱。若需要这种隔离，应另立需求；本版不以新增虚拟机或文件系统框架扩范围。

没有write、引用校验失败、模型未正常结束或任务超限时，不发布为成功成果；保留私有暂存和失败原因。发布后清理失败时仍显示已生成文件及摘要，但整任务为failed-cleanup。取消中止原生会话/上游与工具，晚到响应不得导致发布。

继续使用原生SessionManager；新路径恢复时完整接纳并核验工具消息及关联，界面只显示最终回复和工具摘要。旧文字会话不被新路径解释或迁移。会话固定绑定Agent/Skill/资料快照；如旧任务失败且历史含不完整工具链，保留并拒绝继续该会话，提示新的具体任务预览，不修改JSONL修复。成功任务的后续追问重新批准、重新计费；读取新会话不会获得其他会话的资料。

公开证据只保存版本/摘要/计数、引用ID与范围、结果和独立结论，不保存原始供应商payload、完整资料、私有成果或聊天历史。用户成果在其输出目录可用，不能为了公开证据自动拷贝进Git。

## 8. 验收与离线交付终点

离线使用假SDK、假HTTPS、全新临时资料/成果目录、独立合成账本。合成账本以5053/10000起始仅为验证累计计算，不读取或复制原真实账本。

| 验收 | 必须证明 |
| --- | --- |
| 三阶段生成 | 两个不同领域Skill夹具产生不同身份/方法；合法来源→Plan→Package→合成安装一致，新资源摘要改变使旧批准失效 |
| 真实工具形态 | 假原生事件依次读取Skill、两份资料、write暂存、最终回复；工具结果被带入下一请求，默认约5请求而非硬编码回复 |
| 成果 | 得到一份带可定位引用的report.md，文件字节、摘要、回执一致；不能仅有终端文本就称完成 |
| 权限 | 输入注入、路径越界、链接、文件确认后变动、非法Skill、写入重复、未知工具与伪造tool_result均拒绝 |
| 预算/终止 | 第7个请求、第9个工具、请求并发、每请求失败、费用不足、取消和期限触发不产生额外外联；原字面档位仍一次请求 |
| 会话 | 成功任务追问与新进程恢复保留工具链；新会话隔离，旧/异版本/异资料快照拒绝，失败历史不静默续跑 |
| 交付与失败 | 发布中断、目标出现/身份变化、清理未确认等不能报全成功；旧安装、账本、批准和失败目录完全不改 |

离线阶段交付源码、回归结果、源码闭包、一次整批独立审阅，以及具体安装预览和M3验收准备说明。离线模拟通过不能标记实际SDK工具兼容或真实M3工具质量通过。

实际SDK1.2.0如需合成兼容观察，应在后续具体只读激活/SDK验证预览中列出资源装配和本地假上游、0供应商请求；不另开长期测试批次。需要实际SDK执行必须先批准。安装、激活及真实模型材料/调用上限/费用各有具体预览；尚无实际回执时只写准备说明，不伪造绑定。
