01 / 核心产出

一套方法论，
两类长期产出。

首版以 Codex 为构建端、OpenClaw 为 Runtime；未来适配更多 Coding Agent 与 Runtime，而不改写核心协议。

OUTPUT A

AgentMo 方法论与协议层

面向各类 Coding Agent 与运行时的“造 Agent”标准：明确每个阶段的输入、边界、人工批准与验证证据。

  • Discover → Plan → Produce 合同
  • 提示词、Skills、Tools、Memory 工程规范
  • 版本、证据、审批与失败即停止机制

OUTPUT B

可编译的 Agent Package

把规划确定性地投影为目标运行时可用的包。当前首个运行时目标是 OpenClaw。

  • 通用 Blueprint 与 Build Contract
  • OpenClaw 原生资源与 D-42 运输归档
  • 安装、激活、运行、评估生命周期证据

02 / 能力地图

从资料到 Agent，
每一段都有明确职责。

三阶段分离事实、规划与交付，避免把愿望、声明和运行结果混为一谈。

DISCOVER找证据 · 提炼 Idea

AI 连接已授权的公开搜索、内部数据库/API、MCP、本地文件和用户反馈，形成 Research DB，并提炼值得被 Agent 化的机会。

  • 数据连接器Web、内部数据库、业务 API、MCP、本地与人工信号
  • 证据留存来源、发布时间、采集时间、信任等级与去重
  • 机会发现识别趋势、痛点、未满足流程和可 Agent 化任务
  • Idea Gate将有证据边界的候选 Idea 交给用户确认
PLAN设计 Agent · 定义测试

把确认后的 Idea 转化为可批准的 Agent 设计，同时提前定义它必须通过的测试数据集和失败边界。

  • 系统设计Prompt、Skills、Tools、Memory、RAG、DB 与 Loop
  • 规划合同Design Plan、Blueprint、Build Contract
  • 验证合同Evaluation Contract、Test Dataset、Acceptance Criteria
  • Plan Gate人工批准设计、测试标准与精确授权范围
PRODUCECoding · Runtime · 验收

Codex 等 Coding Agent 按批准合同编写真实实现，经 Runtime Adapter 生成目标包，并执行 Plan 阶段预声明的测试数据集。

  • Coding AgentCodex 先行，未来适配 Cursor、Claude Code、Kimi Code
  • Runtime AdapterOpenClaw 先行，未来支持 Pi、Hermes 与业务方规范
  • 测试执行正常、边界、拒答、安全、恢复和 Runtime 测试
  • 交付证据Package、Run、Replay、Eval、Birth 与 Delivery Report

03 / 首个真实 POC

白领产品经理
研究 Agent

聚焦知识工作与文档、会议与协作、数据分析与决策，为未来电脑智能体的需求判断提供本地证据库。

20 → 0新增记录

两次合格采集：第一次纳入 20 条证据；第二次新增 0 条，验证了最小去重路径。

受控来源采集并写入本地 Research DB
记录来源、时间、可信等级与事实边界
重启后仍可读取 DB、知识文档与 Daily Brief
OpenClaw / DeepSeek 仅基于本地证据回答
缺少事实类证据时明确拒答，不编造

04 / 成熟度与边界

机制闭环已验证，
生产授权仍需逐步取得。

阶段性成果的价值，是准确知道已经证明了什么，也准确知道尚未证明什么。

当前已具备

  • 已验证方法论闭环Discover、Plan、Produce 的核心合同与证据链
  • 已验证OpenClaw POC隔离 Profile、DeepSeek 问答与本地知识使用
  • 已验证基础可信性两次采集去重、恢复、拒答与来源边界
  • POCDashboard可进入隔离环境体验首个研究 Agent

尚未自动启用

  • 未授权定时任务08:00 Asia/Shanghai 仅为 Schedule Preview
