# Node TLS 1.2 单次无凭据诊断预览

旧Node r2与系统curl批次均已执行并关闭，不重放。Node观察到TCP连接但10秒内没有TLS完成；系统curl完成TLS并在3065ms取得HTTP404。它们不是同一时刻、同一解析和同一TLS客户端，不能直接确定根因。

## 本轮离线依据

固定Node24.18.0/OpenSSL3.5.7默认范围为TLS1.2至TLS1.3；本机SecureTransport API头文件的最大版本列表到TLS1.2。curl报告使用SecureTransport，但旧结果没有记录实际协商协议，不能补写成已证实TLS1.2。Node内置源码还表明域名SNI会自动设置，并将选项传入tls.connect；未发现旧探针显式漏传SNI。地址族、ALPN、密码套件、证书信任库和ClientHello实现仍存在差异，本轮不同时调整。

待验证的单一假设：将Node的TLS最高版本限制为1.2后，本次能否完成TLS并收到HTTP响应。离线SecureContext检查已确认该选项生效；这不证明外部网络可达。

## 获批后的唯一操作

- 仅使用已有Node及https.request，向`https://api.minimax.cn/anthropic/v1/messages`发送1次HEAD，无凭据、Cookie或请求体。
- 相比旧Node探针，仅增加`maxVersion: TLSv1.2`；默认最低版本仍为TLS1.2。固定公开User-Agent、Accept、Accept-Encoding、agent:false、服务端证书校验及默认域名SNI保持。
- 不设置IP或地址族，不额外解析域名，不改ALPN、密码套件、CA、系统代理或Agent源码。底层正常系统解析及地址选择可能发生，不把1次应用请求等同于1个TCP连接尝试。
- 使用固定PATH/TMPDIR/LANG白名单环境。仅忽略macOS系统编码变量的键名，不读值；其它额外环境键先拒绝，不读取其值。
- 请求10秒绝对期限，Node执行分支15秒保护期限（含本地预检I/O、请求及结果写入）；结束销毁自有请求、清除计时器并退出，无监听端口或后台服务。
- 单次执行，不跟随重定向、不主动重试、不重启、不补跑；不额外执行curl、默认TLS Node基线、其它端点或模型请求。

## 保存与解释

只保存五项阶段布尔值、TLS协议白名单标签（TLSv1.2/UNEXPECTED/null）、HTTP状态、既有白名单网络错误码、本地期限标志及有界总耗时。getter回归禁止读取IP、证书、响应头、错误文本或堆栈；响应立即销毁，不采集正文。未知协议只记固定UNEXPECTED，不保存原字符串。

任意HTTP状态仅说明本次TLS1.2候选取得响应；失败也不证明供应商不支持TLS1.3。与旧批次存在时间和解析差异，不能单独证明唯一根因、密钥或M3生成可用。探针通过也不自动修改产品传输或授权模型验收。
