# 2026.07.03 — AgentMo v0.1 baseline + runtime evidence spine

## 背景

AgentMo 从 Win9-on-Pi 的实践中抽象出 AgentMother：不是写一个 prompt，而是用 Codex/编程智能体构建另一个可验证的领域智能体。

核心模式确定为：

```text
Discover -> Plan -> Produce
```

也就是先找数据和用户需求，再形成可执行蓝图，最后交给 Codex/Pi/OpenClaw 等 runtime 生产、验证和记录证据。

## 架构决策

采用：

- JSON blueprint 作为 v0.1 canonical executable format。
- CLI-first，而不是 UI-first。
- deterministic core，而不是 LLM-first hidden generator。
- build plan 与 scaffold apply 分离。
- runtime evidence 与 runtime/domain certification 分离。
- OpenClaw 作为 active alternate architecture reference，不把它自动等同于 Pi runtime。

拒绝：

- 在 MVP 初期直接做 SaaS/UI。
- 直接让 AgentMo 自动调用 Codex 改仓库。
- 把 OpenClaw scaffold 视为 Win9 runtime parity certification。
- 在默认测试里依赖真实 provider/network/daemon。

## 非认证边界

本阶段只能说明：

- AgentMo 具备 blueprint/build/runtime evidence spine。
- OpenClaw target 可以被计划、scaffold、记录 run-state。

不能说明：

- Win9 已经在 OpenClaw 上完成领域质量认证。
- OpenClaw runtime 与 Pi runtime 行为等价。
- 任意生成 agent 可生产部署。

## 后续风险

- runtime evidence 仍可能被误解为 runtime certification，后续文档和 birth gate 必须持续阻断这种误读。
- CLI surface 增长较快，后续新增命令需要保持 parse/execute 边界清晰。
- OpenClaw live path 涉及密钥、state、gateway/local transport，必须坚持 value-blind 和 isolated-state。
