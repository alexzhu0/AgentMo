# 2026.08.06 — White-collar black-box POC identity admission repair

## Background

An independent black-box POC used the documented public seed and source
registry through the correct POC checkout. Build, check, brief, restart,
schedule preview, and two isolated OpenClaw/DeepSeek turns succeeded, while
both collections stopped before network access with
`AGENTMO_POC_RESEARCH_INPUT_INVALID`.

## Root cause and change

- `examples/ai-frontier-poc.seed.json` identified the generated workspace as
  `ai-frontier-poc`, while `examples/white-collar-research.sources.json`
  identified its registry as `white-collar-research-poc`.
- Collection correctly failed closed because persisted collection state and
  the registry belonged to different agents. SSRF controls, source allowlists,
  and transport policy were not involved and were not relaxed.
- The public seed now binds to the same `white-collar-research-poc` identity as
  the public registry.
- `poc collect` now rejects a mismatched registry at the CLI boundary with the
  bounded diagnostic `sources.agentId must match workspace.agentId.` It does
  not expose either identifier value or a local path.

## Evidence

  `/private/tmp/agentmo-white-collar-blackbox.pf4irg/BLACK_BOX_POC_REPORT.md`
  at `sha256:e81189a7db80198fbaa1d420200ab2ad710a7acacd256417bad7658f6b551384`.

## Non-certification boundary

The repair proved only local input compatibility and bounded diagnosis. At
that checkpoint, the reported black-box run remained `PARTIAL`: it contained
no successful live collection, dynamic Research DB records, or successful-path
idempotence evidence. The later final acceptance below supersedes that POC
status, but not the schedule, delivery, domain-quality, or production boundary.

## Synthetic DNS proxy compatibility

A second independent collect retest confirmed that the identity repair worked,
then stopped both attempts at
`AGENTMO_DISCOVERY_LIVE_PRIVATE_DESTINATION`. The host resolver mapped the
fixed public source hostnames into `198.18.0.0/15`. The report is
`/private/tmp/agentmo-white-collar-collect-retest.cUTC90/BLACK_BOX_POC_REPORT.md`
at `sha256:1bd6d1999c354b3fd0ceb6134105bcdcc1ab377eb4c18b7279b5f1acdc81e544`.

The default `public-only` policy is unchanged. `poc collect` now offers an
explicit `--network-mode synthetic-dns-proxy` mode with a deliberately narrow
contract:

- only the four fixed public POC hostnames may use `198.18.0.0/15`;
- IP-literal targets, redirects, loopback, RFC1918, link-local, and every other
  reserved range remain rejected;
- hostname-authenticated TLS must succeed before a synthetic address response
  is admitted;
- no proxy value, response body, credential, or local path is retained as
  evidence.

The first live attempt through that path exposed a Node 24 compatibility bug:
the pinned lookup callback returned a single address when `https` requested
`{ all: true }`, producing `ERR_INVALID_IP_ADDRESS`. The callback now returns
the exact single-address or address-array shape requested by Node.

The collector also isolates bounded per-source retrieval failures. One failed
source no longer rolls back already validated records from another source;
the CLI reports successful, retrieved, and failed source counts. A collection
still fails closed when every registered source fails.

## Final independent black-box acceptance

The fresh isolated acceptance run completed through the same public CLI and
the explicit `synthetic-dns-proxy` mode. Its report is
`/private/tmp/agentmo-white-collar-final-poc.rmjWaz/FINAL_BLACK_BOX_POC_REPORT.md`
at
`sha256:9ae50a4b3b93f536caafff69f2a4001918f62f27e5b20b72480c9d1cd086a77d`.
An independent SHA-256 recomputation matched that value.

- First qualifying collection: 2 successful sources, 2 retrieved sources,
  2 bounded failed sources, 20 newly admitted records.
- Second qualifying collection: 2 successful sources, 1 retrieved source,
  2 bounded failed sources, 0 newly admitted records, 20 retained records.
- A fresh process restored the 20-record Research DB; the daily brief retained
  8 evidence items and 0 gaps.
- Short isolated OpenClaw/DeepSeek questions cited local knowledge/document and
  data-analysis evidence. A meeting/collaboration question correctly refused
  to promote community signals into facts.
- The schedule remained `proposal-only`, `not-authorized`, and unexecuted; no
  delivery occurred.

This is `PASS` for the bounded acceptance run. It does not certify all four
sources as healthy: two failed in each collection. The restricted execution
carrier still lacked DNS, and one broad model question timed out before the
short evidence-bound questions succeeded. Dynamic Research DB records are not
yet a production Wiki projection, schedule activation is absent, and domain
quality, complete source coverage, delivery, production readiness, and wider
OpenClaw compatibility remain unproved.
