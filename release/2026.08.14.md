# 2026.08.14 — Discover Agent Idea Candidate proposal contract

## 背景

2026.08.12 的权威架构明确 Discover 应从证据提炼 Agent Idea 并交给人类确认。
第一个代码垂直切片需要让提议内容可校验、可发现、可精确绑定证据，同时不能让
普通调用方在同一内容文件中自声明人类批准或进入 Plan 的权限。

## 范围

- 新增 durable subject `agent-idea-candidate` 与 schema identity
  `agentmo.agent-idea-candidate.v1`。
- 新增 closed JSON Schema、生产 validator、validator-valid minimal template、artifact
  registry/admission 接线与 exact Discovery DB companion binding。
- 新增只读 CLI `agentmo agent-idea-candidate-report`，支持 bounded human/JSON
  diagnostics、evidence-kind/trust composition 与不足警告。
- 将生产模块纳入 npm files、Builder release/tarball inventory、`npm run check` syntax
  closure 与 Node 20 owned syntax batch。
- 新增 Stage 2 回归，证明 design-plan、user-need 与 approval 路径不把 Candidate
  接受为权威。

## 架构决策

- 内容与授权分离。Candidate 不包含 `humanDecision`、approval state、enter-Plan
  permission、build/runtime authority 或 organization-authentication claims。
- `source.discoveryDb` 精确记录 identity、subject 与 digest；CLI 同时 exact-admit
  Candidate 和唯一 Discovery DB companion。
- 每个 `evidenceIds` 项必须在 exact admitted DB 中解析为唯一 fact。缺失、重复或
  歧义 ID fail closed；schema 不要求某个领域专属 fact kind。
- `extraction_field` 只能是 planning lead；报告必须警告它不证明 user need、value、
  capability、domain quality 或 Plan readiness。
- 固定 `certificationBoundary` 仅允许 `proposalOnly:true`，其余需求、价值、能力、
  质量、Plan/production readiness 与 enter-Plan/build/runtime authority 均为 false。
- 未来 Decision Artifact 必须独立设计并 exact-bind Candidate digest；本轮不实现。

## 非认证边界

- Candidate 是 proposal，不是 human decision、approval 或 Plan input。
- Candidate 与其 report 不证明用户需求、价值、Agent 能力、领域质量、Plan readiness、
  production readiness、部署或运行时成功。
- exact digest 与 evidence resolution 只证明有界机制绑定，不证明被引用事实为真。
- 本变更不提供 Decision Artifact，不修改 Plan/Produce 权限，不实现自动 Idea 生成，
  不绑定 OpenClaw，也不依赖外部开发工作流或插件。

## 后续风险

- 独立 Decision Artifact 的身份、签发者/authority、Candidate digest exact-binding、
  revision/rejection 语义与进入 Plan 的消费边界仍需单独设计和审批。
- 自动提炼 Idea 的质量评估与人类交互流程尚未实现。
- 当前报告的 composition 是机械统计，不能升级为语义或质量认证。
