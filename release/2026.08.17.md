# 2026.08.17 — 合并后 aggregate gate 收口

## 背景

`main` 合并 Candidate、OpenClaw runtime guard、Node 20 receipt 与聚合测试修复后，
一次完整检查暴露了两类只在高负载组合中出现的测试门禁问题：private continuation
夹具的 child watchdog 短于它自己的边界观察窗口，以及 immutable successor 场景仍与
其余 packed behavior 用例共享一个高成本 lane。

本轮只收口测试合同与验证编排；没有修改 AgentMo 生产实现、OpenClaw runtime、
artifact schema、安装权限或认证边界。

## 范围与决策

- private continuation 的完整边界观察窗口固定为 15 秒，child watchdog 固定为
  30 秒，并由回归测试要求 watchdog 至少覆盖观察窗口再加 15 秒余量；terminal
  Promise 在创建后立即附加 rejection handler，避免尚未进入消费阶段时产生
  `PromiseRejectionHandledWarning`。
- 保留严格 fail-fast，不增加 retry、不放宽 continuation admission，也不更改生产
  timeout。
- 将 `uses one immutable successor selection for receipt, hook, doctor, and behavior`
  从 `packed-behavior` 精确拆到 `immutable-successor` lane；其他 behavior 用例在该
  lane 明确 skip，successor 在 `main` 与 `packed-behavior` 中明确 skip。
- `npm run check` 的末端顺序固定为：
  `main -> durable-fs -> packed-hook-chain -> packed-behavior -> immutable-successor`，
  并继续使用 `&&` 保持前一 lane 失败时后续不得运行。

## 验证证据

```text
npm run check
```

聚焦验证还包括：

最终事实以本记录提交前再次执行的文档门禁与 `git diff --check` 为准。
