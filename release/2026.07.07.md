## Post-commit live promotion fix

在首次尝试 support-triage OpenClaw live-success promotion 时，真实 runtime run 已成功：

- `execution.status=success`
- `execution.live=true`
- `exitCode=0`

但 `run-eval --expect-status success` 按安全门失败，因为 run-state 对 unstructured stdout/stderr 保存了 raw preview。修复后：

- structured OpenClaw JSON 仍保存 structured summary；
- unstructured stdout/stderr 只保存 digest/length/line-count metadata；
- `rawOutputPreviewStored=false`；
- 被篡改成 `raw-output-preview` 的 execution/evidence 仍 fail-closed；
- `birth-report` 同步识别 `unstructured-digest-summary` 为非 raw preview evidence。

这项修复只改变证据持久化安全语义，不把 live-success 提升为 domain certification。

## Stage 3 delivery closure docs/scaffold 回补

本次最小回补文档与生成文案，覆盖 AgentMo 三阶段：

1. 搜索/收集数据，形成结构化 discovery database。
2. 根据用户需求结合数据库，规划新 Agent。
3. 完成 Agent 设计、实现、交付证据闭环。

当前 `domain-eval` / `delivery-report` 属于第三阶段交付闭环：

- `domain-eval` 是独立领域质量证据，输入应是 sanitized、bounded domain cases 或经审查的 eval artifact。
- `delivery-report` 聚合并重验 blueprint、build-state、run-state、run-eval、birth-report、可选 domain-eval；它不自行认证 runtime、domain 或 production approval。
- `birth-report` 仍只证明 mechanism/runtime birth evidence，不证明 domain quality 或 production approval。
- support-triage deterministic fixture 只证明机制和样例 case coverage，不是生产客服认证。
- 不声称 OpenClaw production/domain certified。
