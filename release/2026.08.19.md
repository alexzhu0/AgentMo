# 2026.08.19 Plan Decision Entry canonical writer + Builder bootstrap exact-frame + Node 20 evidence closure

## 背景

独立黑盒 POC 在 Plan 阶段发现公开 stale-head flag 文案与实现不一致，且一个合法的
sequential Decision Entry draft 没有受支持的、在 digest authority 之前确定排序字节的
公开写入路径。本轮修复该 Plan decision-ledger 公共合同；不把 Plan approval 机械绑定到
验收数据集，也不进入 blueprint、build-contract 或 Produce。

同一未提交批次随后修复了 packed Builder 首次 bootstrap graph delivery 对 peer EOF 的
错误依赖；该修复不改变其他 CLI 写入路径或 POC gate。

## 范围与决策

- 新增 `agentmo decision-ledger canonicalize-entry --entry <draft> --out <absent>`：它在
  digest 展示前将未批准 draft 的 `sourceRefs`、`decisionRefs` 与 `requirementRefs`
  确定为 byte-sorted reference arrays。duplicate 仍拒绝；append 和 admission 对已经
  digest-bound 或批准的字节只验证、不排序、不改写。
- Plan ledger 的公开 stale-head flag 统一为 `--expected-head-digest`。
  `--expected-head-sha256` 仍是 Builder-only spelling，并在 `decision-ledger` 拒绝。
- Registry admission 现与 decision-ledger/schema 的 Unicode code-point bounds 对齐，故
  canonicalize→append 不会只因非 BMP text 的 UTF-16 length 而拒绝；既有字段上限未放宽。
- Builder bootstrap graph 的 fd3（loader）和 fd4（snapshot verifier）是 parent-owned、
  专用的单帧通道。parent 注入 canonical decimal `N`，范围为 `1..24 MiB`；reader 只读取、
  digest 并解释恰好 `N` 个 bytes，`N` 到达即有界返回，不等待 peer EOF。非法、零、
  非 canonical 或超限长度，以及 `N` 前 EOF/short read 都 fail closed。`N` 后 bytes 永不
  解释为 graph；peer 保持打开时，本合同不声称能够检测或拒绝未来的第 `N+1` byte。
- Canonical writer 使用 bounded no-follow draft read、caller-owned non-group/world-writable
  parent、private 0700 stage、one-link exact-byte verification 与 create-only publication。
  已批准的狭义 same-UID threat model 明确排除调用期间对 output parent、private stage 或
  target namespace 执行 link、rename、unlink 或 write 的同 UID 并发对手：调用方必须独占
  并保持这些路径稳定。它不是 same-UID concurrent filesystem transaction；可观察的
  pre-publication identity/symlink 异常仍 fail closed，且发布后绝不按公开 pathname 回滚或删除。
- 包含该 shipped module 的 npm files、Builder release/tarball inventory、host syntax
  check 与 exact I/O surface ownership 已同步；未放宽任何 allowlist。
