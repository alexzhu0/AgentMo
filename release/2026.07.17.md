# AgentMo 2026.07.17 — Installed Codex hook recovery bridge

## Outcome

Phase 2 Plan 02-08 connects exact installed Codex SessionStart, PreCompact and PostCompact deliveries to the projected project-local launcher, receipt-backed runtime, canonical Builder hook reducer and durable checkpoint CAS. Reloaded deliveries are idempotent, later legal compactions receive distinct deterministic epochs, and the final UAT interface records digest-only challenge observations.

This is bounded mechanism evidence. Authenticated normal-trust Codex delivery and clean-host support UAT remain pending under BLDR-07 and BLDR-01.

## Delivered controls

- Checkpoint schema `agentmo.builder-checkpoint.v2` adds an exact durable Codex delivery cursor and optional challenge/observation slot. Exact canonical v1 bytes load through deterministic in-memory migration without rewrite or fabricated state.
- Delivery identity binds only exact event type, a digest of bounded `session_id`, normalized SessionStart source and deterministic compaction epoch. Raw session IDs, transcript paths, outputs and payload claims are not persisted.
- SessionStart replay reconstructs its original identity, sequence and event digest. PreCompact advances the epoch from idle/completed state; PostCompact requires the current PreCompact; replay returns a byte-preserving no-op.
- The generic event ledger remains bounded to 64 entries. If a SessionStart ages out after 32 legal compaction pairs, its durable cursor plus exact reconstructed digest still classifies the installed replay as `duplicate`; checkpoint bytes, inode and mtime remain unchanged, while unrelated evicted events retain generic `stale` semantics.
- Hook payload cannot choose project, workflow, adapter, stage, event sequence, checkpoint digest, next action or approval. The canonical hook-only reducer remains the sole workflow transition implementation.
- Challenge state is armed only through checkpoint CAS. One matching applied installed delivery records exact runner, release, receipt, event, before-checkpoint and reduced-after-checkpoint digests plus count one. Direct reducer calls, mismatches and replay cannot satisfy it.
- The installed runner accepts at most 64 KiB, exact-admits only three trigger names, launches the fixed adjacent runtime through `process.execPath`, uses a minimal child environment, caps combined output at 16 KiB and kills after two seconds.
- Child failures, timeout, overflow, unknown events and aliases expose no child stderr, payload or transcript. PreCompact emits `{}`; newly applied SessionStart/PostCompact emit one bounded proposal; duplicates emit `{}`.
- The internal launcher route is not in public help. It derives the fixed project, receipt, runner and checkpoint locations from the installed layout, then admits project scope, exact receipt, full release inventory, runner bytes and checkpoint before event construction.
- Default modules with an external receipt digest are classified as projected before any plugin-presence heuristic when their canonical root has the exact `plugins/agentmo/runtime/agentmo` suffix. A decoy runtime-local `plugin` directory therefore cannot suppress receipt admission; the packed regression proves rejection leaves the checkpoint byte-identical.
- `src/builder-hook-bridge.js` is included in the fixed 59-asset release inventory (54 runtime assets), package syntax chain and fresh packed import closure.
- The prior mechanism-only behavior evaluator now runs the admitted runner in a transient fixed-adjacent synthetic harness. It remains explicitly non-certifying and does not mutate the installed project.

## Plan 02-09 addendum — value-blind Codex UAT candidate admission

### Outcome

Phase 2 Plan 02-09 adds the formal `agentmo.codex-uat.v1` candidate route. A fixed eleven-scenario value-blind operator-observation run can be journaled through absent-output begin, exact admitted external observations or checkpoint-derived hook records, identity-bound ordered CAS and complete-only finalization, then exact-admitted against the current pristine activated receipt, owner/consumer state, current host observation, project-local launcher and installed hook runner. The prior nine-scenario packed behavior evaluator remains a separate mechanism-only lane.

This is a candidate mechanism, not clean-host support or real-session evidence. Every resulting candidate and evaluator report keeps human admission required, `realCodexSessionVerified: false`, and activation, host behavior, Agent Package, domain and production certification false.

### Delivered controls

- The durable candidate schema accepts only release, install receipt, owner, consumer, project scope, host, auth, isolation, launcher, hook-runner, external-basis, scenario-set and ordered-result digests plus fixed enums and false certification flags.
- The ordered scenario set is `skill-discovery`, `session-start`, `user-prompt-non-trigger`, `manual-pause`, `pre-compact`, `post-compact`, `restart-resume`, `duplicate-replay`, `second-compaction`, `upgrade-visibility` and `uninstall-visibility`.
- Each scenario stores only ID, pass/fail, before/after checkpoint digests, a bounded observation digest and fixed producer provenance. Non-hook scenarios require canonical exact-digest external observations; hook scenarios are derived only from an exact checkpoint challenge binding runner, release, receipt, event, scenario, challenge, before/after state and count. Raw prompts, payloads, transcripts, stdout/stderr, paths, environment and credentials have no schema field.
- `builder codex-uat begin` creates only an absent run; `record` requires the exact current run digest, fixed next scenario and exactly one external scenario or checkpoint digest; `finalize` requires all eleven passing results and publishes only to another absent path.
- Journal replacement uses random exclusive no-follow staging and retains both admitted run and stage handles. It writes, syncs and verifies the complete next bytes, rechecks both exact identities, publishes with one atomic rename and syncs the parent directory where supported. Pre-publication failures never truncate or alter prior bytes/inode; post-rename failures never roll back the next value; cleanup unlinks only a stage inode AgentMo created while that exact inode still owns the path.
- `builder behavior --uat` requires one exact install-receipt digest and one exact UAT digest. It rejects stale release, receipt, owner, consumer, project, host, launcher and hook-runner bindings before returning a candidate report.
- Consumer admission does not trust whole-ledger digest agreement alone: it rebuilds the canonical expected entry from admitted project scope, current release and receipt selector, requires exactly one matching entry in the current ledger, and requires its digest to equal the receipt's `consumerEntryDigest`.
- Wrong digests, partial or reordered runs, raw caller-built basis/results, unknown/duplicate scenarios, synthetic producer kinds, official/authenticated authority claims in caller artifacts, trust bypass, non-isolated launch facts, stage write/sync/verify failures, symlinked/foreign stages, late target swaps and caller verification claims fail closed.
- The UAT module is present in the fixed 60-asset release inventory, including 55 runtime assets, the explicit syntax chain and clean packed import/help closure.
- The exact production I/O inventory owns all 18 UAT journal surfaces under Phase 02 Plan 09.
- `src/builder-hook-bridge.js` was consumed unchanged; its SHA-256 remains `d30feaf880decec310b0d576a056322aa462d935d4106596ee214df0f8b5f643`.

### Follow-up authority and crash-safety deviation

The initial 02-09 implementation called exact-digest, caller-writable observations a real-session candidate and rewrote the retained journal inode in place before attempting restoration on failure. Follow-up review showed that neither claim was supportable: exact bytes do not make operator-reported auth/trust facts official, and restoration cannot make partial in-place publication crash-safe. The route is therefore deliberately downgraded to `value-blind-operator-observation-candidate`, every real-session/certification flag is false, and journal CAS now stages complete bytes and publishes once by rename. This correction narrows evidence authority and changes no Builder hook-bridge authority.

A final P2 review also found that a receipt and ledger could be rewritten consistently while omitting the current project's consumer. The evaluator now reconstructs and canonically digests that expected entry; missing, scope-mismatched or release-mismatched entries fail even when receipt, ledger and UAT digests all agree. Selector drift remains structurally rejected by the canonical consumer helper.
