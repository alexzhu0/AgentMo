# AgentMo 2026.07.11 — Canonical migration apply

## 背景

Phase 1 已具备闭合的 legacy JSON migration registry、whole-batch preview 和 deterministic receipt model。本次补齐显式 --out apply，使适用的 in-memory plan 能写入一个新建专用目录，同时保持源工件不变，并让任何不完整、身份丢失或被篡改的目录都不能成为官方成功输出。

## 范围

- 新增 capability-gated migration filesystem publisher。
- 保留默认 preview；只有显式 agentmo migrate ... --out <new-dir> 才进入 apply。
- 新建输出目录固定为 owner-only 0700；canonical payload、receipt 和 instance marker 使用 exclusive/no-follow retained handles。
- 先完成全部 output handle pre-open，再写入并同步 payload；deterministic receipt 后写；committed marker 最后写入并同步。
- 新增独立 verifier，重新检查 requested-path binding、parent/directory identity、marker、receipt、精确 file set、文件模式与逐文件 digest。
- 新增 stable value-blind apply result/error formatter，以及 parent swap、nth open/write/sync、tamper、source mutation 和 source preservation coverage。

## 架构决策

### 采用

- Apply 在任何 output mkdir 之前检查 no-follow flags、current-uid parent ownership、parent mode、稳定 BigInt dev/ino、source file sync 和 retained parent-directory sync 能力。
- 直接把不存在的 --out 创建为 0700 uncommitted staging；不使用 pathname rename 宣称原子发布。
- Instance marker 只保存版本、opaque token、requested-path digest、plan digest、parent identity、directory identity 和 staging/committed state。
- 任一 final verification failure 都通过已确认归属的 retained marker handle 恢复 staging；失败输出不能在条件恢复后重新成为可验证成功。
- Path identity 丢失时不执行 recursive cleanup，也不修改未经确认的 replacement handle；保留 owner-only orphan staging 并返回 AGENTMO_MIGRATION_ORPHANED_STAGING 与 opaque token。
- Output parent 与任一 source-containing directory identity 相同时在 mkdir 前拒绝，确保 migration 不改变源目录 entries。

### 拒绝

- 未采用临时目录加 pathname rename 的“绝对原子”说法。标准 Node 20 没有 portable openat、renameat 或 unlinkat，无法消除所有 pathname race window。
- 未采用 capability failure 后的降级写入。
- 未采用 rm -rf、recursive delete 或对 identity 不确定路径的 cleanup。
- 未把 instance marker、receipt 或 apply result 当作 domain、runtime 或 production quality certification。

## 非认证边界

本记录证明的是确定性 migration mechanism、失败关闭 publication contract 和本地 adversarial regression evidence。它不证明：

- Node 20 的独立真实运行 lane；
- 任意 filesystem 上不存在 pathname race；
- OpenClaw runtime execution 或 live-success；
- domain quality、domain-wide certification、production readiness 或 deployment approval。

declared-ready 仍只证明 deterministic wiring；live-success 仍只证明一次隔离运行。Migration receipt、committed marker 和本记录都不能替代 Birth/Delivery/domain evidence，也不能自我认证。

## 后续风险

- Phase 1.2 仍需在真实 Node 20 lane 复验 capability behavior。
- 不支持 directory fsync、read-handle file sync、no-follow flags、stable ownership/mode 或 stable dev/ino 的平台会在 output mkdir 前返回 AGENTMO_MIGRATION_PLATFORM_UNSUPPORTED；不会降级。
- 标准 Node pathname APIs 仍存在不可消除的 race window。本实现依靠 retained handles、反复 identity binding、committed-marker-last 和 fail-closed verifier，保证检测到不确定性时不报告官方成功，而不是宣称 pathname 原子性。
- Identity 丢失可能留下 0700 orphan staging；这是避免删除 replacement 或未知资产的保守行为，需要由拥有 opaque token 的上层恢复流程另行处理。
