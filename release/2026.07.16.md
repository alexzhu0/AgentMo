# AgentMo 2026.07.16 — Codex Builder projection, activation and safe lifecycle

## Outcome

Phase 2 Plan 02-05 projects a packed, receipt-managed AgentMo runtime and launcher into a clean project. Plan 02-06 adds explicit preview-bound `user` host activation through fixed official Codex interfaces. Plan 02-07 extends exact lifecycle controls to every runtime byte, removes only the current project's shared-selector reference, and makes zero-reference selector removal a separate user-owner operation with external evidence admission. Projection, activation, trust and host behavior remain separate evidence levels; BLDR-01 and BLDR-07 therefore remain pending.

This record contains bounded paths, commands, counts, hashes, status, and remaining risk only. It contains no secret values, raw transcripts, provider payloads, or raw process output.

## Delivered controls

- One deterministic 58-asset release inventory: five plugin assets plus the fixed package metadata, launcher, Codex host adapter, and complete relative ESM import closure.
- Receipt and marker schema v2 report `projected`, not `installed`, and keep activation, host behavior, and domain quality false.
- Projected executable admission requires an exact caller-provided receipt digest from outside the mutable projection. Local receipt, marker, and assets cannot certify themselves.
- Repeat setup requires the externally admitted prior receipt digest and binds it, the receipt identity, release identity, project root, and parent-directory identities into the approved plan.
- Publication revalidates the authorized parent ledger during staging, publish, and terminal verification. Failed receipt-last publication moves the canonical receipt entry into a non-authoritative quarantine and performs no later pathname-based deletion.
- Doctor uses a diagnostic-only, non-executable inventory when the receipt is missing, corrupt, or inconsistent; it returns bounded read-only findings without upgrading diagnostic observations into trust.
- The Codex host adapter fixes selector, argv, timeout, output bound and environment projection. It exposes value-blind installation, enablement, source/release, skill, hook, trust and availability facts only.
- The App Server adapter waits for and validates the initialize response before sending its fixed query set, keeps stdin open until exact results 2/3/4 arrive, and fails closed on EOF, timeout, oversize, unexpected, duplicate or error responses.
- AgentMo selector ownership is stored separately from a canonical sorted project-consumer ledger outside Codex-owned state. Project receipts own one consumer reference and never gain selector deletion authority.
- Setup re-observes the host immediately before mutation, rejects project/source drift, and writes owner/consumer evidence only after official add and post-observation. Before retracting a published activated receipt, it proves the reservation, exact current owner/ledger identities and the reservation again. If rollback authority is no longer exact, the canonical receipt and verified matching owner/consumer evidence remain committed together instead of creating split-brain evidence.
- An externally anchored canonical v2 receipt can transition to v3 through receipt-last replacement. Preview binds the exact v2 digest, bytes, inode and parent identities; setup revalidates them after immediate host observation and before mutation, while terminal failure restores the exact prior receipt bytes.
- Compensation respects shared-state dependencies: if a sibling advances the consumer ledger, failed ledger restoration stops before removing the selector owner.
- State publication uses no-clobber CAS and preserves competing bytes; canonical state-root checks reject symlinked ancestors. Missing enablement, disabled hooks and failed observations are unavailable rather than successful.
- Doctor activation certification requires both consistent activation evidence and a pristine current projection; moved or scope-mismatched projects remain diagnostic only.
- Upgrade/uninstall derives every runtime target from the canonical packed release inventory and binds exact digest plus file identity through staging, mutation seams, no-clobber publication and receipt-last terminal checks. A staged candidate retains the exact inode created through AgentMo's open handle, is revalidated immediately before linking, and is cleaned up only while its digest, inode, size and single-link state still match; a same-byte replacement inode is preserved.
- Activated project uninstall exact-CAS removes only its deterministic consumer. Sibling consumers remain untouched; the final consumer leaves the selector and owner intact and returns `host-owner-action-required`.
- A release-changing activated upgrade cannot replace a selector while sibling references or separate owner authority remain. Same-release activated upgrade preserves the v3 receipt and shared references.
- Selector removal is an independent `user`-scope operation requiring explicit intent, one-to-one external owner/ledger digests, an AgentMo-created owner, an exact empty ledger, fixed official removal and post-observed absence.
- Successful selector cleanup moves the exact owner/ledger pair out of canonical authority into one private retained transaction directory. It does not perform a non-atomic double deletion that could split the evidence pair on failure.
- A fixed durable user-state reservation serializes owner/ledger mutation. Activation holds it through receipt publication, project lifecycle holds it through receipt terminal or rollback, and owner removal holds it through the official command and evidence cleanup. Same-byte marker replacement and stale/malformed reservation state fail closed without TTL takeover.
- Contamination discovered after activated receipt publication prevents receipt retraction and host rollback. Retirement is attempted only as a commit; if exact retirement fails, the canonical receipt, exact host evidence and active blocking reservation remain visible for evidence-aware recovery.
- Long reservations retain exact prior owner/ledger inodes: abort restores those same inodes no-clobber, while commit moves them into the retired non-authoritative reservation archive. Same-byte new-inode competitors are never treated as AgentMo's publication.
- Terminal project/receipt postconditions and transaction-record validation establish the irreversible host commit before retained-prior cleanup begins. Partial finalization, later observation failure, or reservation-release failure cannot restore a ghost consumer after project bytes and receipt have reached their terminal state.

## Evidence boundary and remaining risk

- `projected` and `declared-ready` prove bounded mechanism wiring only. They do not prove that Codex installed, enabled, trusted, or invoked the plugin.
- Diagnostic-only package inspection is not an executable release trust root and cannot produce support, activation, host-behavior, domain-quality, production-readiness, or deployment claims.
- Failed terminal verification may leave an AgentMo-created random quarantine under `.agentmo/builder/` for manual inspection. It cannot serve as the canonical success receipt and is intentionally not deleted through a mutable pathname.
- A successful v2-to-v3 replacement retains the exact prior v2 receipt under a random, non-authoritative private quarantine so pathname races cannot cause deletion of unrelated bytes. Lifecycle cleanup is deferred to the receipt-aware uninstall phase.
- Successful zero-reference selector removal similarly retains the exact owner/ledger pair under one random, non-authoritative private quarantine. Canonical authority is absent, while the pair remains available for manual recovery instead of risking partial deletion.
- Each completed reservation is exact-renamed into a non-authoritative private retained directory. A crashed or altered active reservation intentionally blocks later host-state mutation until an explicit evidence-aware recovery workflow is implemented; it is never stolen by age, PID or caller assertion.
- If that active reservation becomes contaminated after receipt publication, AgentMo intentionally preserves the canonical activated receipt and matching host evidence rather than retracting one authority without the other; the contaminated reservation continues to block mutation.
- Authenticated clean-host Codex UAT, recovery/restart hardening, hook-to-local-launcher event bridging and domain-quality evaluation remain outside this release slice.
- No authenticated session, model call, OpenClaw runtime, provider-backed execution, or production action was performed.
