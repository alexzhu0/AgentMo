# 2026.08.04 — Phase 4 native authority race closure

## Status

Phase 4 package execution remains pre-POC and fail-closed. This change closes
the native authority races found by successive independent deep audits; it does
not authorize install, activation, runtime, domain, Birth, or production.

## Decisions

- Safe-fs and supervisor compiler source is captured once as exact admitted
  bytes and supplied independently to both compiler processes over stdin.
  Compiler outputs are anonymous sealable memfds. A repository-pinned preload
  makes the Node worker and every compiler descendant non-dumpable after each
  exec; the worker seals each output before two stable reads. Safe-fs receipt
  `agentmo.openclaw-fs-build-receipt.v4` and supervisor receipt
  `agentmo.openclaw-process-supervisor-receipt.v3` record the sealed transport,
  pinned preload digest/identity, descriptor authority and independent output
  identities.
- OpenClaw probe private scripts remain named inside the mode-0700 private root.
  The path and retained descriptor must resolve to the same exact identity on
  every authority revalidation. Unknown pathname replacements are rejected and
  preserved; AgentMo no longer unlinks the script pathname. Child Node processes
  execute only the previously captured and digest-verified script bytes supplied
  over stdin, so later same-inode mutation cannot become executable input. The
  preserved synthetic HOME is reported honestly as not discarded.
- Native create-only publication uses an unnamed `O_TMPFILE`, applies and checks
  the exact requested mode independently of ambient umask, then publishes with
  `linkat(..., AT_EMPTY_PATH)`. The helper is non-dumpable, reads and digests the
  retained inode twice before and after publication, and reports observed bytes
  rather than the requested digest. Failed no-replace publication closes the
  unnamed descriptor with no hidden target-root orphan and no pathname cleanup.
- Post-link durability uncertainty now returns `created-uncertain` with exact
  retained identity and digest. Install and journal recovery classify the
  object as AgentMo-owned instead of incorrectly treating it as pre-existing.
- Linux CI rebuilds the preload twice with fixed flags and compares those two
  same-toolchain outputs, independently verifies the committed asset's pinned
  SHA-256, and executes that asset in the same-UID descriptor attack. It does
  not treat different compiler toolchains as byte-identical authorities.
