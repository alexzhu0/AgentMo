# 2026.08.12 — AgentMo canonical architecture clarification

## 背景

阶段性汇报复核发现，旧架构表述容易把 Discover 简化为数据采集、把 Plan 简化为
设计文档、把 Produce 简化为打包，并容易将 Runtime 或外部开发工具放入错误的
架构角色。
本记录收敛 AgentMo 的长期产品逻辑与扩展边界。

## 架构决策

- Data Connector Layer 面向公开搜索、内部数据库与知识库、业务 API、MCP、本地
  文件、人工输入和用户反馈；所有来源先适配为带 provenance、authority、time、
  trust 和 redaction 边界的证据。
- Discover 是机会发现阶段：AI 从已授权来源形成 Research / Discovery DB，识别
  痛点、趋势和可 Agent 化任务，生成带证据与判断边界的 Agent Idea candidates，
  由用户确认、否决或修订。
- Plan 同时形成实现设计与验证合同：Blueprint、Build Contract、Evaluation
  Contract、Test Dataset、Acceptance Criteria 及 hard failures。规划必须提前
  定义如何证明 Agent 达标。
- Produce 由 Coding Agent 执行编码、测试和有界修复。首版构建端是 Codex；长期
  适配目标包括 Cursor、Claude Code、Kimi Code 等 Coding Agent。外部开发工作流、
  规划框架与插件不属于 AgentMo 产品架构，也不得成为 AgentMo 的运行依赖。
- AgentMo 保留 target-neutral Agent Specification，经 Runtime Adapter 投影到
  OpenClaw、Pi、Hermes 或业务方提供的 Agent 架构规范。OpenClaw 是首个实现目标，
  不是永久绑定。
- 权威架构只描述通用平台能力，不包含具体领域 Agent、POC 或客户场景；这些是由
  AgentMo 生产的实例，不是架构组件。
- Produce 必须执行 Plan 阶段预先声明的测试数据集，并保留 build、runtime、eval、
  delivery evidence；任何阶段均不得自我认证后续阶段。
