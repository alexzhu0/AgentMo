# AgentMo 2026.07.12 — Blueprint-to-handoff exact admission

## 背景

Phase 01.1 的前五个计划已经建立精确字节准入、共享持久化策略、Discover/Plan 输入闭合与显式 migration 边界。本次 Plan 06 收束 Produce 入口：让 `validate`、`report`、`plan`、`handoff` 只接受带外提供的 blueprint 字节摘要，并让 handoff 在任何目录、临时文件或最终文件出现前完成整包安全检查。

本记录只覆盖截至 Plan 06 已实际完成并验证的范围。Phase 01.1 尚未完成；Plan 11–13 仍负责输出通道、生成/脚本命令和最终全仓闭合。

## 范围

- Durable registry 新增两个闭合 descriptor：
  - `blueprint`：`agentmo_version = 0.1`
  - `handoff`：`schemaVersion = agentmo.handoff.v1`
- `validate`、`report`、`plan`、`handoff` 的固定 subject 均为 `blueprint`；`design-plan` 仍严格保持 `discovery-db + user-need`。
- 新增严格 `loadAdmittedBlueprint` 与真实 `loadHandoffPackage`；摘要校验、UTF-8/JSON、身份、subject、schema 和内容策略都基于同一次受限文件捕获。
- Handoff manifest 的来源权威固定为 `{identity, subject, digest}`，不保存主机路径，也不采信上游成功标记。
- Handoff builder 只接受 authentic blueprint admission；完整 handoff、精确 manifest 和固定九个文件操作先通过持久化策略与结构校验，再进入共享 atomic text writer。
- `loadBlueprint` 暂时只允许七个机器可检验的后续计划消费者；这些调用分别归属 Plan 07、08、10，不能作为本计划的全局 loader closure 证据。

## 架构决策

### 采用

- Registry resolver 按 descriptor 声明的 identity field 与 identity 联合解析；同时出现 `schemaVersion` 与 `agentmo_version` 会失败关闭。
- Design contract 保持 blueprint 内嵌契约，不创建额外 durable subject。
- Handoff candidate 深度冻结并由模块内 capability 标记；writer 拒绝克隆、伪造、额外文件、重复路径、绝对/父级穿越路径和 manifest/object 脱节。
- `agentmo-handoff.json` 必须逐字节等于 `serializePersistableJson(handoff)`；九个文件全部预检完成后才允许第一个物理写入。
- Runtime 与 domain certification 字段继续固定为 `false`；handoff 只证明安全交接机制，不产生更强认证。

### 拒绝

- 未给缺失 digest 的 blueprint loader 增加静默回退。
- 未把 host path、review reference 或 upstream `ok` 当作 durable provenance authority。
- 未提前修改 Plan 07/08/10 所有 CLI consumer；七个临时消费者保留精确 owner 清单。
- 未放宽共享 persistability kernel 来容纳不安全措辞或候选内容。

本记录证明的是本地 exact-byte blueprint/handoff admission、完整 handoff preflight、确定性最终文件与失败关闭行为。它不证明：

- OpenClaw live execution 或 runtime promotion；
- domain quality、domain-wide certification 或 production approval；
- Plan 07–13 的 artifact family/output/script/docs 最终闭合；
- 七个 transitional blueprint consumer 已完成 exact admission；
- 外部运行环境或独立 Node 20 lane。

`declared-ready` 仍只证明确定性机制证据；`live-success` 仍只证明一次隔离运行。两者都不能自动产生 domain 或 production 认证，handoff 也不能自我认证。

- Handoff/CLI stdout 仍归 Plan 11；当前 I/O inventory 只把 handoff physical sink 标记为 `gated`。
- Generated scaffold、handoff 和 live-smoke 命令的 registry-backed digest rendering 归 Plan 12；维护中的 prose command corpus 归 Plan 13。
- Shared atomic text writer 在底层文件系统错误时不提供九文件事务原子性；本计划证明的是所有候选安全检查发生在首次副作用前，而不是跨文件事务提交。

# AgentMo 2026.07.12 — Scaffold/build-state all-set persistence

## 增量范围

本节只记录 Phase 01.1 Plan 07 在上述 Plan 06 基础上的增量结果：`scaffold` 与 `status` 已从仅路径 blueprint loader 迁移到精确字节准入；build-state 与完整 scaffold 写入集在首次目录或文件副作用前完成验证。Phase 01.1 仍未完成，runtime、后续报告族、stdout 与脚本/文档闭合继续归后续计划。

- Durable registry 新增 `build-state` descriptor，identity 为 `agentmo.build-state.v1`。
- `scaffold` 固定消费 `blueprint`；`status` 固定消费 `blueprint`，且只有提供 `--build-state` 时才增加可选 `build-state` subject。缺路径但多余 binding、给路径但缺 binding、重复 binding 和字节变更均失败关闭。
- 新 build-state 只保存 admitted blueprint 的 `{identity, subject, digest}`、托管相对输出根与每个 operation 的内容摘要；不保存 `blueprintPath`、`outputDir`、`destinationPath` 或宿主路径主权。
- `status` 不仅分别准入 blueprint/build-state，还交叉验证 agent id 与 source identity/subject/digest，拒绝来自另一 blueprint 的有效 build-state。

- 新增 capability-branded product-text writer：schema-owned prompt/skill 策略语言可作为普通产品数据持久化，但 secret-like 值和具体宿主绝对路径仍在任何 mkdir/write 前拒绝。
- Scaffold/build-state 物理 sink 已从 `pending:01.1-07` 转为 `gated`；全部 CLI stdout/stderr 仍保持 `pending:01.1-11`。

## 架构决策

### 采用

- 使用新 identity `agentmo.build-state.v1`，不把旧 `agentmo.build.v1` 的 stable-JSON hash 冒充 admitted byte digest。旧 family 继续保留显式 migration/legacy validator 边界。
- 无显式 `generatedAt` 时写入 `null`，从而使默认 build-state 可复现；该字段不再伪装成实际生成时间证据。
- Product-text lane 只能由模块内 brand 创建；writer 拒绝伪造 wrapper。Portable `./`、`../` 和 `<managed-root>/...` 指令不被误判为宿主路径，具体 POSIX/Windows/home 路径仍被拒绝。
- `--force` 写入前只读检查现有路径组件并拒绝符号链接；写入仍只使用预检时复制出的相同 bytes。
- Birth/delivery 兼容层识别新 build-state provenance shape，同时保持非自认证边界；它们的完整 exact admission 仍归 Plan 10。

### 拒绝

- 未给 `scaffold` 或 `status` 增加缺 digest 回退。
- 未把旧 build-state hash 重新标记成新 byte digest。
- 未在 build-state 中保存 scaffold root、blueprint 文件位置或 operation destination absolute path。
- 未把 schema-owned prompt/skill 文本误当 runtime evidence，也未通过放宽共享 secret/host-path 检测来让候选通过。
- 未实现 Plan 08 runtime artifact gate、OpenClaw 版本 gate、Plan 11 stdout gate或更强 runtime/domain/production 认证。

# AgentMo 2026.07.12 — Runtime artifact admission and transient execution material

## 增量范围

本节只记录 Phase 01.1 Plan 08 在 Plan 07 基础上的 runtime 增量。Runtime plan、run-state 与 run-index 已成为闭合的 durable artifact family；命令恢复依赖 exact admitted bytes 与操作方重新提供的瞬态消息/路径，而不再依赖进程内对象、blueprint 路径或已保存的消息副本。

- Durable registry 新增三个 descriptor：
  - `runtime-plan`：`agentmo.runtime-plan.v1`
  - `run-state`：`agentmo.run.v1`
  - `run-index`：`agentmo.run-index.v1`
- 命令 subject 已闭合：
  - `run-plan -> blueprint`
  - `run -> runtime-plan`
  - `run-report/replay-run/run-eval -> run-state`
  - `status --run-state -> blueprint + run-state`
  - `status --run-dir -> blueprint + run-state + run-index`
- `run-plan` 保存 admitted blueprint provenance；`run-state` 同时保存 immediate input、runtime-plan 与 blueprint exact lineage。Birth/delivery 的 bounded compatibility 通过 build-state 与 run-state 的相同 blueprint digest 关联，不恢复 stable-object hash。
- Durable message record 固定为 `sourceDigest + byteLength + RedactedSummary`。Inline/file 消息 bytes、消息文件宿主路径和复制后的 message artifact 均不进入 runtime-plan、run-state 或 run-index。
- Workspace、OpenClaw source root 与 state dir 只以 `TransientPathRef` 表示。实际路径在 `run` 或 live replay 的执行边界重新提供，runner 使用瞬态 materialized command；durable command 继续保留 `<transient-message>`。
- Runtime environment evidence 使用 exact `SecretPresence`，只记录 allow/present/missing names；credential values 仅存在于 runner 的瞬态 environment map。
- Stdout/stderr 与 message evidence 使用 exact `RedactedSummary`。结构化结果仅保留有界字段与原因摘要；非结构化结果只保留 digest/length/line-count summary。
- Run-state 与最终 run-index candidate 在首次 mkdir/temp/write/rename 前完成 persistability、schema 与 serialization preflight。Index 使用排序 entry array，避免把 operator run id 变成动态证据键；每项保存 exact serialized state digest。
- Replay 只有在本次重新提供的 message bytes 匹配 `sourceDigest/byteLength` 时才标记 `exact`。缺失 material 为 `unavailable`，不匹配为 `reconstructed`；`--require-exact-replay` 在 spawn/write 前失败。
- Nested provenance 的 `identity/subject/digest` duplicate members 现在会在 JSON last-wins parse 前递归失败关闭；原顶层 identity/watch 规则保持不变。
- Runtime state/index physical sinks 已转为共享 persistability writer 并在 I/O inventory 中标记 `gated`；CLI stdout/stderr 仍属于 Plan 11。
- Transitional blueprint consumer 从五个降为三个：仅剩 `birth-report`、`domain-eval`、`delivery-report`，全部归 Plan 10。

## 架构决策

### 采用

- 把 runtime-plan 作为 `run` 的唯一 durable authority；拒绝从 blueprint 或路径参数在执行进程中重新构造计划。
- 把执行命令拆成 durable template 与 transient materialized command。Session selector 可以成为安全、可复现的 durable metadata；消息与宿主路径不能。
- Runtime target verification hints、unsupported surfaces 与 profile evidence boundaries 只保存 digest，避免把 schema-owned policy prose 混入 runtime evidence lane。
- Run-index 使用 entry array 而不是以 run id 为键的 object，以保证任意合法 run id 都不会绕过或误触 secret-like key policy。
- Existing run-index 在 owned mutation path 中先读取并做完整 schema/persistability preflight；所有外部 status consumption 仍要求 index 与 latest state 的独立 exact digest binding。
- Birth/delivery 暂时通过 `runState.source.blueprint.digest === buildState.source.digest` 保持 composed loop；其完整 artifact admission 继续由 Plan 10 负责。

### 拒绝

- 未保留 `executeRuntimeRun(blueprint, ...)` compatibility shim。
- 未持久化 inline message、message-file path、managed message copy、workspace/cwd/state/source absolute path、env value或 runner output body。
- 未从保存的路径读取消息来推断 replay exactness。
- 未让 `run-eval --require-exact-replay` 在缺失重供消息时静默通过。
- 未加入 Phase 1.2 OpenClaw runtime/version gate，未放宽共享 persistability carrier 规则。
- 未提前关闭 Plan 09/10 的 observation/report loader family，也未把 CLI output channel 标记为 gated。
