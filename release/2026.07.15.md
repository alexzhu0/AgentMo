## Implemented architecture

### Packed project-local runtime

- The npm release carries one canonical Codex plugin and a complete co-released Node import closure.
- Project setup projects the launcher at `plugins/agentmo/runtime/agentmo/bin/agentmo.js`; the installed skill does not depend on an AgentMo checkout or global `PATH` entry.
- Setup is preview/apply. The apply step must use the exact project-bound plan digest; repeated setup must also exact-admit the current receipt bytes.
- The current dry-run package contains 61 npm entries. The Builder's fixed release inventory contains the plugin assets plus the project-local runtime closure and rejects missing, added, remapped, symlinked, hard-linked, or duplicate assets.

### Explicit user-host activation and ownership

- Project-only setup never mutates user-host state. Host activation requires explicit `--host-scope user` preview/apply.
- AgentMo invokes only fixed official Codex interfaces and does not write Codex cache, config, or trust state directly.
- The shared selector has a separate AgentMo owner record and a canonical sorted project-consumer ledger. The activated project receipt publishes last after current host visibility and the exact owner/consumer bindings are rechecked.
- Codex hook trust is human-owned; installed/enabled/skill/hooks visibility does not by itself prove trusted delivery or support.

### Read-only doctor

- `builder doctor` reports project projection, current release/receipt state, host visibility, installation, enablement, skill/hooks visibility, trust, owner, consumer, launcher, hook-runner, checkpoint, and agent observability as separate bounded facts.
- Doctor does not repair, activate, trust, rewrite, or promote evidence. Missing, corrupt, moved, modified, or scope-mismatched state remains explicit and fail-closed.

### Sibling-safe lifecycle

- Upgrade and uninstall use exact receipt admission, preview-bound plans, three-way byte comparison, retained inode identity, no-clobber publication, and receipt-last terminal checks.
- Project uninstall removes only its exact consumer. Sibling consumers preserve the shared selector; the final consumer returns owner action required rather than deleting user-host state.
- Selector removal is a separate zero-reference user-owner operation requiring exact owner and empty-ledger digests plus the fixed official remove interface.
- Durable reservations serialize activation, project lifecycle, and selector-owner removal. Modified, unknown, hard-linked, symlinked, stale, competing, or irreversibly split state is preserved and blocks unsafe mutation.

### Installed hook to checkpoint CAS

- Exact `SessionStart`, `PreCompact`, and `PostCompact` deliveries traverse the installed fixed runner, adjacent project-local launcher, receipt/release admission, canonical hook reducer, and checkpoint compare-and-swap.
- Hook input cannot select project, stage, approval, next action, launcher, or checkpoint authority.
- Durable delivery cursors make an exact replay write-free after restart or bounded-ledger eviction. A later legal compaction receives a new deterministic epoch.
- The bridge can record only one matching digest-only challenge observation; direct reducer calls, wrong challenges, wrong scenarios, and replays cannot satisfy that slot.

### Formal value-blind UAT path

- `builder codex-uat begin` publishes only an absent run from an exact canonical basis artifact.
- `record` requires the exact current run digest, the fixed next scenario, and exactly one exact external scenario artifact or challenge-bearing checkpoint.
- `finalize` requires all eleven ordered passing records and publishes only to an absent candidate path.
- `builder behavior --uat` separately exact-admits the candidate against the current release, receipt, owner, canonical current-project consumer, ledger, project, host observation, launcher, and hook runner.
- Journal replacement uses a random same-directory exclusive no-follow stage, retained prior/stage identity checks, atomic rename, supported parent sync, and owned-stage-only cleanup. Pre-publication failure preserves prior bytes and inode.
