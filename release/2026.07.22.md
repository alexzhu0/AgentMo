## 当前实现范围

- `builder deactivate` 通过 append-only lifecycle authority 追加 tombstone；不删除 receipt、projected runtime、immutable release、host evidence、UAT evidence 或历史 lifecycle evidence。
- `builder reactivate` 追加 activation successor。`builder upgrade` 只发布到 immutable version-qualified release path，并追加新选择；不会覆盖 canonical genesis receipt。
- 隐藏的 deprecated `builder uninstall` 仅映射到非删除 `deactivate`。Purge、selector removal、host projection replacement、canonical replacement 和 `--remove-host-selector` 全部 fail closed。
- Shared append authority 先以 sequence claim 建立 durable ownership，再发布 operation data；claim-only、prepared、committed 与 aborted prefix 都可在 fresh process 中读取并精确收敛，竞争失败不会留下需要删除的 poisoning stage。
- Stage、hard-link 与 directory sync effect 通过 retained-directory-bound POSIX helper 执行；identity-change-and-restore schedule 不能把被拒绝的 effect 留在替换目录。
- Install attempts、shared host authority、checkpoint/journal、private UAT authority 与 observation/candidate publication 使用 append-only、absent-only 或 retained-link admission。Interrupted install 可精确 re-admit stage/publication bytes，追加 superseded outcome，并在不删除历史 evidence 的条件下允许新 setup；durable host claim 可由 exact retry 恢复。
- Lifecycle selection 通过一个 canonical admission 解析 genesis 或 immutable version-qualified successor。Hook、Doctor、behavior、package 与 UAT consumers 使用同一 active path/version/digest；runtime-changing successor fail closed。
- Formal UAT public surface 已收敛到 `start`、exact-head `record`、`scenario-arm`、`terminal failure|interruption`、`inspect`、`resume` 与 packed `continue`。旧 `begin`/`finalize`、`--uat` 与 `builder-codex-uat=` syntax 不再接受。
- Behavior admission 绑定完整 attempt journal、exact current head、immutable candidate leaf、current receipt 与 release chain；不能把手写 candidate 和无关 receipt 拼接成 11/11 报告。
- Formal UAT 只接受 committed release-set 中的 exact retained/public inode pair，并校验 expected role、完整 package/release 7-tuple、bounded gzip/USTAR archive 与 extracted package bytes；不再接受 generic single-link file fallback。Continuation 的 deactivation arm 绑定 pre-deactivation、final-scenario 与 candidate-ready 三个合法 head，exact retry 可从任一原始合法输入收敛。
- Release producer 将已 sync 的 retained commit inode 以 absent-only hard link 发布到 public path，按 documented directory-sync order revalidate bytes、inode、link count 与 parent identities。
- Hook checkpoint append 在 commit 前重新验证 lifecycle/head/active receipt；continuation arm 先于 tombstone，recovery 可验证 bounded hook successors 与 final deactivation challenge，避免 post-deactivation checkpoint mutation。
- Packed verifier 的 `preview` 只读。`decide approve|reject` 只产生 caller-reported、nonterminal、journal-preserving 的结果；`humanAuthorityVerified` 保持 `false`，`externalDecisionAuthorityRequired` 保持 `true`。
- Builder v1 以 POSIX ownership、mode、hard-link 与 directory-sync 语义为支持边界；shared platform gate 是 public/internal CLI、installed hook、direct scripts、POSIX child 与 exported Builder I/O APIs 的 first-effect guard。macOS/Linux 是当前支持平台，missing owner identity、`O_DIRECTORY`、`O_NOFOLLOW` 或其他 unsupported semantics 都在 stdin/filesystem/process effect 前 fail closed。
- Public help/docs 对 `--journal` 与 `--uat-journal` 统一使用 `<journal-file>`；只有从目录内派生 `attempt.journal` 的 packed continuation/verifier surface 使用 `<attempt-dir>`。

## 公开迁移约束

已有 projected-v2 canonical receipt 不能再由 setup 原位替换为 activated-v4 receipt。该路径返回 `AGENTMO_BUILDER_INSTALL_IMMUTABLE_SUCCESSOR_REQUIRED`。迁移规则是：

1. 保留 canonical genesis receipt 与其 bytes；
2. 后续版本使用 `.agentmo/builder/releases/<bundle>/...` 下的 immutable version-qualified successor；
3. 通过 append-only lifecycle event 选择 successor；
4. 新的 absent installation 如需 user-host activation，应在 initial setup 时显式选择 `--host-scope user`；
5. 不通过 delete、rename、receipt rewrite、selector removal 或 purge 强制迁移。
