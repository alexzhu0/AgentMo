# 2026.07.27 — Independent POC entry and evidence-semantics remediation

## Status

An independent AgentMo-only black-box POC failed before Discover because an operator could not discover the required fields for `agentmo.discovery.v1` or `agentmo.user-need.v1`, and exact-digest admission collapsed field failures into a generic `AGENTMO_UNSUPPORTED_ARTIFACT`. After that entry surface was repaired, an incremental rerun reached Plan and exposed a second semantic issue: manifest `extraction_field` declarations were overcounted as collected evidence. This record covers the bounded Phase 2 entry and evidence-semantics remediation only. Live collection, Wiki generation, a runnable Agent Package, real OpenClaw execution, domain quality, and production readiness remain unproven.

## Scope

- Added `agentmo artifact-contract discovery-manifest|user-need --json`.
- Exported field-level JSON Schemas and minimal templates that pass the production validators.
- Added bounded subcommand help for `discover-report`, `discover-pack`, `discover-workspace`, and `need-report`.
- Preserved fail-closed exact-digest admission while returning secret-safe field requirement messages for a registered identity whose fields are invalid.
- Included the new contract module in the deterministic Builder runtime inventory and npm package closure.
- Reconciled the exact I/O inventory without adding a filesystem, network, host-mutation, or secret-reading surface.
- Prevented declaration-only `extraction_field` facts and unverified source chunks from producing `supported` Stage 2 coverage.
- Restricted `supported` coverage to multiple matching source-derived `source_chunk` facts with `derived`, `trusted`, or `verified` trust.
- Removed source-wide extraction-field expansion from each fact's matching text so one declaration list cannot amplify unrelated matches.

## POC evidence

- Overall POC result before remediation: FAIL.
- `runtime-check --target openclaw --json`: PASS for the current Node process only.
- `discover-report`, `discover-pack`, and `need-report`: exit 1 with `AGENTMO_UNSUPPORTED_ARTIFACT`.
- Plan, Produce, and real OpenClaw execution: not run because the Discovery Contract gate was not satisfied.
- POC did not use GSD, Superpowers, OMX, subagents, browser/search, `.env`, user-host mutation, or repository writes.

The POC report remained outside the repository and was reviewed read-only. Its machine-local locator and raw command transcript are intentionally excluded from release evidence.

The incremental black-box rerun confirmed that contract export, bounded help, field diagnostics, manifest materialization, design-plan generation, blueprint drafting, handoff, and scaffold commands are publicly operable. It also confirmed that the generated scaffold contains declarations and documentation but no executable collector, Wiki, scheduler, deduplicator, or restart-recovery implementation.

Replaying the exact incremental POC Discovery DB and user need after the semantic fix changed the Plan result from 13 `supported` plus 1 gap to 0 `supported`, 13 `partial`, 1 `missing`, and 14 governed gaps. The command still exits successfully because Stage 2 can produce an honest governed plan; it no longer represents desired extraction fields as retrieved evidence.
